# Encore

Личный музыкальный телеканал. Целевые платформы: Windows, Linux, macOS.

Сейчас: прототип Этапа 0, не готовый музыкальный сервис.

## Запуск

Node.js 22.12+:

```powershell
cd apps/desktop
npm ci
npm run dev
```

Открыть http://localhost:1420. Это браузерная проверка, не проверка desktop.

Для desktop дополнительно нужны Rust и системные зависимости Tauri:
https://v2.tauri.app/start/prerequisites/

```powershell
npm run desktop
```

Проверки: `npm run check`, `npm test`, `npm run build`.

Документация: [ТЗ](docs/00-README.md), [решения](docs/DECISIONS.md), [статус](docs/IMPLEMENTATION-STATUS.md).

Windows debug executable после сборки: `apps/desktop/src-tauri/target/debug/encore.exe`.
UI smoke test (с подменённым YouTube API): `npm run test:ui`. Локально использует установленный Chrome; в CI — Playwright Chromium. Для CI браузер устанавливается через `npx playwright install chromium --with-deps`.

## Подключение аккаунта в текущем прототипе

В PowerShell один раз выполните:

```powershell
& 'C:\Users\Skar\Documents\Encore\apps\desktop\src-tauri\target\debug\yandex-probe.exe' --save-token
```

Ввод токена скрыт; после проверки аккаунта он сохраняется в системном хранилище (Windows Credential Manager / macOS Keychain / Linux Secret Service). На Windows сохранение и чтение из desktop проверены. На Linux/macOS эти операции ещё требуют проверки. Нет fallback в открытый файл. Удаление сохранённого доступа: та же утилита с `--forget-token` (это локальное удаление, не отзыв на стороне Яндекса).

При запуске Encore создаёт новую сессию без autoplay. Есть очередь, загрузка следующей порции, ручной переход к следующему треку и привязка YouTube-ссылки к текущему треку. Экспериментальный автоподбор подготавливает три ближайших трека. После явного Play полное завершение видео продолжает очередь; на старте autoplay нет. Базовая история фактических стартов и одна сохранённая ручная ссылка на трек хранятся в SQLite. Синхронизация playback feedback пока отсутствует. При отсутствии безопасного совпадения нужен ручной URL, трек автоматически не пропускается.

«Миниплеер» меняет вид и размер того же окна/плеера, «Поверх окон» включает topmost явно. Из развёрнутого окна можно перейти в минирежим и обратно. Размер и topmost пока не сохраняются между полными запусками.

## Native smoke test (Windows, opt-in)

Нужны `tauri-driver` в PATH (`cargo install tauri-driver --locked`) и Edge WebDriver той же версии, что установленный WebView2. Путь драйвера задаётся ENCORE_EDGE_DRIVER, либо `.tools/edgedriver/msedgedriver.exe`. Собрать desktop перед проверкой.

```powershell
$env:ENCORE_LIVE_YANDEX='1' # Только если пользователь уже подключил аккаунт
$env:ENCORE_LIVE_YOUTUBE='1' # Реальный YouTube, громкость 0
node scripts/native-smoke.mjs
```

Тест запускает отдельное native-окно, проверяет source session/следующую порцию, Play/Pause/seek, mini/topmost и single instance, затем закрывает окно. Токен и ответы API не выводятся. Авторизованный тест создаёт рекомендационную сессию, но не отправляет feedback о прослушивании. Уже открытый Encore нужно закрыть перед тестом.

Подробности экспериментального поиска и ограниченной проверки: [S10](docs/S10-MATCHING-SPIKE.md). Для opt-in native matching smoke задайте также `ENCORE_LIVE_MATCHING=1`.

Аудиовыход выбирает ОС; собственного переключателя устройства нет. SQLite `encore.sqlite` хранится в системном каталоге данных Encore, отдельно от credential store. В истории доступны поиск, воспроизведение и очистка с подтверждением (последние 100 подходящих записей). Длительность прослушивания, фильтр по дате и постраничная история ещё не реализованы. Native smoke использует отдельную тестовую БД в `.tools/native-test-data`, доступную только debug-сборке, и проверяет testMode перед изменением данных.

Поиск Яндекс Музыки: запрос вроде «рамштайн» показывает исполнителей, треки, альбомы и плейлисты. Просмотр не переключает текущую музыку. Для запуска есть кнопки трека/списка; конечные списки сохраняют порядок и подгружают следующие страницы. API ограничен размером ответа; очень большие/нестандартные коллекции ещё требуют проверки.

Добавлены Previous (первый раз в начало, второй за 3 секунды назад в очереди), повтор одного клипа, сохранение громкости и mute. Repeat-queue, полноценный cross-source Previous и несколько favourite-клипов пока отсутствуют. Автоматический выбор YouTube больше не требует совпадения канала с исполнителем: подходящие кандидаты сравниваются по просмотрам, сомнительные предлагаются для выбора.


Закрытие окна скрывает Encore в трей и сохраняет музыку/очередь. Меню значка: открыть, Play/Pause, полный выход. Если трей недоступен, закрытие завершает приложение. Повторный запуск восстанавливает существующее окно. Системные медиаклавиши подключены через SMTC / MPRIS / Now Playing; обычных глобальных хоткеев нет.

После уведомления ОС о сне/пробуждении остаётся пауза до Play. На Windows при воспроизведении запрашивается запрет автоматического сна/выключения дисплеев; ручной сон доступен. Реальный sleep/wake, аппаратные медиаклавиши и работа этого среза на Linux/macOS ещё требуют проверки. Автоматический native smoke проверяет скрытый таймлайн, восстановление, tray-команды, публикацию SMTC и доставку имитированных power events.

В истории доступны «Воспроизвести», «Следом» и «В конец». Добавление сохраняет текущий клип и состояние Play/Pause, использует сохранённую ссылку записи и не заменяет остальные треки. В «Моей волне» после добавленных треков продолжаются рекомендации.
