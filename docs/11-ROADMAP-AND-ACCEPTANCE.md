1. Стабильная компьютерная версия, включая понятное управление мониторами.
2. Официальный сайт и распространение проверенных сборок.
3. Браузерный пульт для телефона в домашней сети: QR-код/подтверждение, поиск, очередь, клипы, реакции, громкость и экраны. В desktop остаётся единственный плеер и звук; телефон только управляет. До реализации проверить защищённое подключение, pairing и отзыв доступа (прежний Q05 остаётся открытым).
4. После обратной связи решить, нужны ли самостоятельный веб-плеер и Android/iOS-приложения; сейчас они отложены.

Приёмка пульта: неподтверждённое устройство не управляет desktop; команды используют существующую очередь/coordinator; подключение не создаёт второй YouTube-плеер и не запускает музыку само; потеря связи с телефоном не останавливает воспроизведение на компьютере. ## Следующая сессия — 2026-11-06: понятная настройка мониторов (REQ-057)

- Обнаруживаемость: заметный вход в вывод на телевизор/управление экранами из основного окна, без обязательного поиска в настройках. Приёмка: пользователь может найти и начать вывод из основного интерфейса; затем выбрать экран и содержимое. Точное место кнопки определить при реализации. Не подразумевать сетевой casting, если телевизор не доступен как монитор.

- Пользователь сначала выбирает монитор, затем «Клип» или «Визуализатор»; для визуализатора выбирает тип на выбранном мониторе.
- Один клип одновременно на нескольких экранах; визуализаторы тоже можно повторять, типы выбирать независимо, искусственного лимита количества нет.
- Приёмка: изменение содержимого одного экрана не меняет выбор на остальных; клипы остаются зеркалами единственного источника, без повторной загрузки и дублирования звука. Основное окно поддерживает режим только управления и списков.
- Это согласованный UX и предстоящая реализация, не заявление о готовности визуализаторов или multi-mirror.

### Обязательные проверки автономной волны

- Серия рекомендаций: без совпадения / needsReview / запрещённый embed / таймаут / рабочий клип → поток доходит до рабочего без ручного выбора, порядок пригодных треков сохранён.
- Следующая порция и подбор пополняются до конца буфера; завершение текущего клипа не требует нажатия Next.
- В fullscreen сбой загрузки/зависание сменяют трек, fullscreen и единственный слышимый источник сохраняются.
- Pause во время поиска/подготовки отменяет позднее автоматическое Play; sleep/wake остаётся paused.
- Общий сбой сети не вызывает неконтролируемую прокрутку/запросы. Автовосстановление выполняется только при сохранённом play intent.
- Длительный прогон (включая скрытое окно и fullscreen) без ручных действий; отдельно фиксировать максимальные паузы и причины исчерпания буфера. Недоступность внешних сервисов не выдавать за гарантированное 100% воспроизведение.
- Поиск/выдача прокручиваются независимо; видео и транспорт остаются видны.

Проверено на Windows 2026-11-04: renderer fail/skip/order/Pause/fullscreen сценарии, native hidden60мин без ручных действий (16переходов, maxobservedgap5сек при опросе5сек) и отдельный WebViewoutage20сек. Linux/macOS runtime и физический sleep/lock остаются открытыми. Детали и границы в IMPLEMENTATION-STATUS.md.
