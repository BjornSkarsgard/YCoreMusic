2026-11-05, REQ-029/030/031/032/057. Дополняет Windows single-player mirrors из docs16. Отдельный файл `scene-layouts.json` в прежней app data directory хранит настройки каждого стабильного monitor ID: положение относительно рабочей области, размер в логических единицах, windowed/maximized/fullscreen, topmost и явно скрытое состояние. OFF удаляет только запись выбранного экрана. SQLite/credentials/очередь не менялись.

## Поведение

- При запуске восстанавливаются настроенные сцены без запуска музыки. При автозапуске в трей восстановленные сцены остаются скрытыми до явного Open.
- Отключённый монитор сохраняет свою настройку: окно скрывается, DWM handles снимаются, на другой экран оно не переносится. После возвращения того же стабильного ID окно восстанавливается с прежними параметрами. Проверка подключения выполняется раз в секунду, поэтому мгновенная реакция до системного перемещения окна не гарантируется.
- Пользовательский крестик сохраняет hidden; tray Open выражает намерение восстановить скрытые сцены, но не показывает сцену отсутствующего монитора на другом. OFF не восстанавливается автоматически.
- Положение запоминается только на назначенном стабильном мониторе: системный перенос при отключении не перезаписывает сохранённое положение координатами другого дисплея. При изменении DPI/рабочей области размер и положение ограничиваются доступной областью.
- Для временных/неоднозначных monitor IDs автоматическое сохранение/восстановление не обещается, существующее предупреждение сохраняется.
- В диалоге можно выбрать сохранённый отключённый экран и выключить его. Ошибка сохранения показывается явно, текущие окна продолжают работать.

## Реализация

`scene_layout.rs`: типизированный JSON version1, строгие поля/валидация ID и конечной геометрии, ограничение размера входного файла, запись во временный файл с rename. Повреждённый/будущий формат не перезаписывается; показывается предупреждение. Неизменённая конфигурация не записывается каждый tick. Новых зависимостей нет.

Операции открытия/off и восстановления сериализованы существующим Scenes mutex; revision не позволяет позднему restore воскресить окно после пользовательского Off. Поллинг не трогает плеер, аудио, FPS/качество визуализаторов или настройки дисплеев ОС. `scene_test_connected` доступен только main/debug/testMode и фильтрует набор реально подключённых мониторов только для тестового manager — не меняет Windows display settings.

## Проверка

- Rust62 PASS/9 opt-in ignored; в том числе независимые настройки, targeted Off, атомарный roundtrip и сохранение файла при blocked/будущем формате.
- Targeted renderer5 PASS: выбор экранов, поздний первоначальный ответ, независимые окна, отключённый сохранённый экран и ошибка сохранения без pageerror.
- Полный renderer101 PASS/1 skipped, fmt/Clippy и обычная Windows debug сборка PASS.
- Native single-host + `YCORE_SCENE_LAYOUT_SMOKE=1` PASS: реальное видео/два зеркала, сохранение записей двух мониторов, имитация disconnect/reconnect без изменений ОС, tray Open не переносит отсутствующий экран, тот же engine epoch, настоящий полный Quit и новый запуск приложения с восстановлением окна на нужном экране без autoplay; Off удаляет сцену. Mini/topmost/maximized/singleinstance после перезапуска PASS.

Оборудование: Windows 10 build19045, три реальных подключённых монитора. **Физический unplug HDMI, сон/блокировка, Windows11 и большой парк мониторов ещё не проверены.** Не объявлять имитацию аппаратным PASS. На Linux/macOS дополнительные зеркала и их recovery пока недоступны, общий план поддержки платформ не изменён.

Команда: сборка и запуск из docs16 с дополнительной переменной `$env:YCORE_SCENE_LAYOUT_SMOKE='1'`. Тест использует изолированный `YCORE_TEST_DATA_DIR`, читает только созданный им scene-layouts.json; личный токен/аккаунт/рекомендации не затрагивает.
