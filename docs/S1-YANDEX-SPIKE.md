# S1 — Яндекс: план проверки

Статус: НЕ ПРОВЕРЕНО. Требуется аккаунт пользователя; токен в чат не передавать.

## Границы

Адаптер Яндекса работает только в backend/native слое. UI получает метаданные и состояние, не credentials. Секрет вводится локально с маскировкой и хранится через системное защищённое хранилище: Windows Credential Manager, macOS Keychain, Linux Secret Service. Пока хранилище не реализовано, не сохранять токен на диск.

## Порядок

1. Зафиксировать версию неофициальной библиотеки и доступный session API; не считать legacy radio автоматически эквивалентным My Wave.
2. Проверить авторизацию и доступ к персональной станции без вывода личных данных/credentials в лог.
3. Создать новую сессию без autoplay. Получить серверный batch; присвоить ordinal в полученном порядке.
4. Проверить продолжение сессии на 20+ рекомендациях и следующем batch. Повторы сервера не удалять произвольно.
5. Feedback отправлять только по фактическим действиям/прослушиванию. Не имитировать прослушивание или skips ради прохождения критерия 20 треков.
6. Проверить expired token, offline, rate limit; отметить реальное поведение без автоматического перехода на другой источник.
7. Сохранить обезличенный отчёт PASS/PARTIAL/FAIL. Наличие методов в библиотеке не означает успешный spike.

## Локальная утилита первой проверки

Реализован `yandex-probe` (Rust, опциональная feature), отдельно от desktop UI и будущего backend. Использует HTTPS API напрямую по наблюдаемому контракту библиотеки, а не утверждает поддержку полного My Wave session API.

В интерактивном терминале Windows:

```powershell
cd C:\Users\Skar\Documents\Encore\apps\desktop\src-tauri
cargo run --features yandex-probe --bin yandex-probe
```

Или запустить собранный `target\debug\yandex-probe.exe` из терминала. Токен вводить только в скрытый prompt, не в аргумент команды, файл, переменную CI или чат. Утилита не получает токен автоматически и не читает браузерные cookies. Если готового токена нет, сначала нужен отдельно проверенный способ входа — установка случайных расширений не требуется.

Два GET-запроса: account/status и первая порция legacy rotor user:onyourwave. Редиректы запрещены, TLS проверяется, сетевые запросы ограничены по времени, тело ответа ограничено 2 МБ. Тела ошибок и личность аккаунта не печатаются. В консоль выводятся только результат и track IDs с ordinal; никакой feedback не отправляется. Token buffer очищается при освобождении; HTTP-библиотеки могут создавать собственные копии в памяти.

Успех этой утилиты — только PARTIAL S1: новый session API, следующий batch и 20+ рекомендаций требуют отдельной проверки. При ошибке достаточно сообщить категорию ошибки, без токена и полного ответа API.
