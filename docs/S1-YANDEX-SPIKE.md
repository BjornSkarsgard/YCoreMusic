# S1 — Яндекс: план проверки

Статус: НЕ ПРОВЕРЕНО. Требуется аккаунт пользователя; токен в чат не передавать.

## Границы

Адаптер Яндекса работает только в backend/native слое. UI получает метаданные и состояние, не credentials. Секрет вводится локально с маскировкой и хранится через системное защищённое хранилище: Windows Credential Manager, macOS Keychain, Linux Secret Service. Пока хранилище не реализовано, не сохранять токен на диск.

## Порядок

1. Зафиксировать версию неофициальной библиотеки и доступный session API; не считать legacy radio автоматически эквивалентным My Wave.
2. Проверить авторизацию и доступ к персональной станции без вывода личных данных/credentials в лог.
3. Создать новую сессию без autoplay. Получить серверный batch; присвоить ordinal в полученном порядке.
4. Проверить продолжение сессии на 20+ рекомендациях и следующем batch. Повторы сервера не удалять произвольно.
5. Feedback отправлять только по фактическим действиям/прослушиванию. Не имитировать прослушивание или skips ради прохождения критерия 20 треков.
6. Проверить expired token, offline, rate limit; отметить реальное поведение без автоматического перехода на другой источник.
7. Сохранить обезличенный отчёт PASS/PARTIAL/FAIL. Наличие методов в библиотеке не означает успешный spike.
