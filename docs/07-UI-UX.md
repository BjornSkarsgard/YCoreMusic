# Интерфейс и пользовательские сценарии

## Визуальный язык
Киноэкран с минимальным оверлеем, современная тёмная/полупрозрачная glass UI, адаптивные цвета. Видео — главный элемент; без навязчивых панелей. Интерфейс на русском.

## Основные экраны
1. **Splash:** логотип, анимация, **реальные** этапы и ошибки загрузки (backend, DB, auth, monitors).
2. **Now Playing:** видео/визуализатор, постоянные title+artist, контролы при наведении, seek bar, время, repeat, like/dislike, source.
3. **Sources:** My Wave, понравившиеся, плейлисты, альбомы, исполнители, поиск, Smart History.
4. **Queue:** текущий трек, следующие элементы, ручные вставки, источник каждого элемента.
5. **History:** хронология, поиск, повтор, Play now/next/end, очистка с подтверждением.
6. **Video selection:** YouTube поиск/URL, список избранных, удаление/сброс.
7. **Monitors:** карточка каждого дисплея, scene video/visualizer/off, preset, FPS, quality, info panel, fullscreen, topmost.
8. **Settings:** аудиоустройство, громкость, автозапуск, управление доверенными телефонами, статус интеграций, диагностика.
9. **Connection/Errors:** авторизация Яндекса, отсутствие устройства, buffering, API outage, отсутствие клипа.

## Управление
- Space Play/Pause; Left/Right seek ±5 с; Up/Down volume ±5%; F11 fullscreen; Esc exit fullscreen. **Только в активном окне**, игнорировать при focus в input/textarea/contenteditable.
- SMTC/media keys глобально; нажатие Previous соответствует двойной логике 3 с.
- Mouse hover/drag seek: только временная метка, **никаких кадров**.
- Управление скрывается через 3 с per-monitor, info panel не скрывается.

## Уведомления
- Windows toast notifications **никогда** не использовать.
- Внутри приложения: 5-секундный Undo дизлайка, отсутствие устройства, необходимость логина, retry состояния.
- Ошибки должны объяснять действие: «Устройство недоступно — воспроизведение приостановлено; подключите устройство и нажмите Play».

## Поведение жизненного цикла
- Первый запуск: onboarding авторизации, выбор аудиоустройства, первичная настройка сцен; без autoplay.
- Следующие полные запуски: новая My Wave-сессия, READY_PAUSED.
- Закрытие любого окна: скрыть именно его, не останавливать звук. Tray Open восстанавливает скрытые окна, но не `OFF`.
- Автозапуск Windows (OFF по умолчанию): в трей, без воспроизведения.
- Пробуждение из сна: восстановить соединения и позиции, **PAUSED**.
- Win+L: музыка продолжается, на экране системная блокировка; после unlock восстановить сцены.

## Доступность и масштабирование
- Поддерживать Windows DPI scaling и разные размеры дисплеев.
- Читаемость контраста, клавиатурный фокус, кнопки с accessible labels, обработка long titles.
- Не обещать полностью безрамочный drag/resize без тестов Tauri.

## Миниплеер / картинка в картинке (REQ-050, REQ-051)

Согласовано: компактный режим текущего проигрывания, минимум функций, включаемое «поверх всех окон», использование на одном мониторе. Смена режима сохраняет текущую композицию, позицию, очередь и pause/play. Развёрнутые источники, история и настройки остаются в полном интерфейсе.

Предложение для первой реализации (состав кнопок ещё не согласован отдельно): Play/Pause, следующий трек, громкость, переключатель «поверх окон», возврат в полный интерфейс. Миниплеер можно перемещать и менять размер; предусмотреть читаемые элементы управления и минимальный размер YouTube embed. Нативный browser PiP не является обязательной реализацией — нужен пользовательский сценарий компактного desktop-окна.

Предпочтительный эксперимент: менять представление существующего окна, сохраняя тот же плеер; не создавать второй IFrame ради минирежима. Если нужны отдельные окна — предварительно доказать единственность audio authority и непрерывность воспроизведения.

## Поиск и базовые контролы: реализованный срез

Поиск Яндекса открыт отдельной панелью: debounce 400 мс, четыре раздела, карточки коллекций, треки, «Ещё результаты»/«Ещё песни», запуск списка. Список можно просматривать во время музыки. Старые ответы поиска/открытия коллекции игнорируются после нового запроса. Текст результатов добавляется через textContent.

Previous: первый раз seek(0), второй за 3 секунды — назад по текущей очереди, с сохранением pause/play. Есть repeat-one и выключение повтора; repeat-queue пока не реализован. Громкость и mute сохраняются в webview origin storage; это только несекретные UI-предпочтения. В mini доступны Previous/Play/Pause/Next/mute/volume; repeat/seek-кнопки остаются в полном виде. Native minimum mini size увеличен, чтобы управление помещалось.

## Обновлённый интерфейс 2026-11-04

Выбрана «Сцена»: крупное видео слева, независимая боковая панель. Транспорт выровнен по центру, repeat слева, громкость справа. Fullscreen расширяет видео на всю поверхность, управление появляется нижним центральным оверлеем при движении мыши и скрывается через 3 секунды бездействия; hover/drag и клавиатурный фокус сохраняют доступность.

«Моя музыка» содержит реальные собственные/сохранённые плейлисты и любимые треки. «Обзор» — чарт и текущие подборки. Просмотр не меняет музыку; запуск явный. Список коллекции имеет возврат с сохранением выдачи/scroll. Внизу боковой панели — альтернативные видео текущей песни с превью, названием, просмотрами и длительностью, переключение не двигает музыкальную очередь. Like/dislike находятся под видео, Undo дизлайка — внутри приложения на 5 секунд.

## История: дозагрузка и ошибки (2026-11-04)

История загружает по100 прослушиваний, кнопка «Более ранние прослушивания» добавляет следующие, сохраняя текущую музыку. Поиск сбрасывает курсор; старые результаты временно неактивны до ответа. Ошибка чтения оставляет предыдущие записи с пояснением и повтором. При подтверждённой очистке кнопки блокируются до ответа, ошибка показывается внутри диалога. Избранные клипы и текущая очередь сохраняются.

## Предложение подключения Яндекс Музыки при запуске — 2026-11-05

Утверждено пользователем: если подключение не сохранено, при запуске предложить вход с объяснением возможностей (волна, поиск, личные плейлисты/любимое, реакции), кнопками «Войти в Яндекс»/«Позже», флажком «Больше не предлагать» и путём для отложенного входа «Настройки → Яндекс Музыка → Войти в Яндекс». Отказ от напоминания хранится как локальная настройка без credentials и не отключает ручной вход. При сохранённом подключении диалог не появляется; кнопка настроек — «Сменить аккаунт», при отказе авторизации — «Войти снова».

## Окно только с управлением — REQ-053

Явный режим CONTROLS показывает панель управления/поиск/списки без клипа, визуализатора и пустого слота для них. Например, клип воспроизводится на телевизоре, а основной монитор используется только для управления. Это согласованное исключение из прежнего правила постоянно видимого видео в обычной Scene layout. Режим выбирается независимо для каждого окна и сохраняется вместе с размещением. Реализация относится к будущему мультимониторному этапу.

## Полезная площадь CONTROLS — дополнительное уточнение пользователя 2026-11-05

REQ-053 дополнен: режим только управления — полноценная самостоятельная компоновка, а не обычная «Сцена» со скрытым/пустым видеоблоком. Освободившееся место используется для большего числа одновременно видимых списков и элементов управления.

Рабочая компоновка для реализации: основная область — поиск/медиатека/открытый плейлист; отдельная постоянно видимая область — текущая очередь со следующими треками; нижняя полоса — трек, transport/seek/volume/repeat/reactions. Оставить доступными альтернативные версии клипа (статичные превью разрешены), историю и управление размещением/содержимым других окон. Списки должны иметь собственную прокрутку, а transport оставаться доступным. Переключение между поиском/плейлистом не скрывает очередь и не прерывает клип на ТВ. Более широкое окно показывает больше полезных колонок/строк, а не растягивает пустую сцену; узкое сворачивает второстепенные панели.

Набор приоритетных списков и контрольных действий — согласованное направление, точные ширины/порядок панелей — рабочее предложение до реализации/просмотра. Не заменять уже работающий Scene UI этим режимом принудительно.

Первый реализованный срез REQ053: селектор «Содержимое окна» → «Только управление». Основные списки занимают центр, очередь имеет собственный scroll справа, альтернативные клипы под ней, текущий трек и transport закреплены снизу. Исходные DOM-списки и coordinator сохраняются; preference основного окна локально сохраняется, без autoplay. Миниплеер временно показывает клип, возврат восстанавливает выбранную компоновку. Отдельные окна/мониторы, visualizer и полностью независимый audio authority ещё не реализованы этим срезом; см. ADR030.
