# Музыкальный телевизор — навигация по ТЗ

Актуальное название проекта: **YCore Music (YCore)**, произношение «Юкор Мьюзик». Your Music. Your Core, Your World. Карта переименования и совместимости: [14-BRANDING.md](14-BRANDING.md).

**Статус:** согласованное продуктовое ТЗ для локальной разработки в Codex. **Платформы:** Windows, Linux, macOS (REQ-049); основная нативная приёмка пока Windows11. **Язык интерфейса:** русский (архитектура допускает локализацию). **Версия спецификации:** 1.0, 2026-11-03.

## Что строим

Текущая проверка переносимости и границы платформ: [19-PLATFORM-READINESS.md](19-PLATFORM-READINESS.md).
Десктопное приложение, которое берёт музыкальную последовательность из Яндекс Музыки (в первую очередь «Моя волна»), находит соответствующие клипы YouTube и показывает их как непрерывный музыкальный телеканал. В «Моей волне» неподходящие/недоступные клипы обходятся автоматически ради непрерывного потока видео. Для других сценариев аудио с визуализатором остаётся возможным только после технической проверки источника. Несколько мониторов, один общий аудиопоток, телефон как пульт в LAN.

## Правила для Codex
1. Прочитай **этот файл**, затем `01-PRODUCT-DECISIONS.md`, `02-ARCHITECTURE.md` и `11-ROADMAP-AND-ACCEPTANCE.md` до изменения кода.
2. Для конкретной подсистемы используй профильный файл по таблице ниже. Не подменяй согласованные требования удобными реализациями без фиксации компромисса.
3. `10-RISKS-AND-SPIKES.md` — обязательные проверки перед обещанием результата. Неподтверждённые возможности помечены **SPIKE**, а не реализованы «на глаз».
4. Не смешивай **согласованные требования**, **предлагаемые технические решения** и **открытые вопросы**. Решения в `01` имеют приоритет над архитектурными предложениями.
5. Начинай с вертикального прототипа: авторизация → список треков → подбор → один клип → управление → сохранение состояния. Не пытайся сразу построить все мониторы и визуализаторы.
6. Не помещай токены в UI, логи, URL, репозиторий или мобильный пульт. Не обходи ограничения YouTube/Яндекса скрытыми загрузками/извлечением аудио.
7. Вести `docs/DECISIONS.md` (новые ADR) и `docs/IMPLEMENTATION-STATUS.md` (сделано/не сделано/блокеры) в рабочем репозитории.

## Приоритет требований
1. Явно согласованные решения (`01`) > 2. детальные сценарии в профильных файлах > 3. технические предложения (`02`, `09`) > 4. дефолты (`13`). При противоречии **остановись и зафиксируй вопрос**, а не делай молчаливый выбор.

## Нефункциональные принципы
- Нет автозапуска музыки при старте/пробуждении; единственная общая сессия и единый источник звука.
- Нельзя терять порядок рекомендаций «Моей волны» из-за задержки поиска видео.
- Отказоустойчивость без скрытого переключения аудиоустройства.
- Работа в трее и при заблокированном Windows, насколько позволяют ОС/WebView2.
- Никакого встроенного блокировщика рекламы, прокси или скачивания YouTube-медиа.
- Тестируемое поведение важнее точных предположений о неофициальных API.
