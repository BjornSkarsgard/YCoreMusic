# S10 — Экспериментальный подбор клипов

Дата: 2026-11-03. Windows 11 / WebView2 156.0.4314.58. Статус: PARTIAL.

## Реализация

Native Rust adapter запрашивает только публичные metadata search results YouTube Music (наблюдаемый контракт ytmusicapi). Никакой авторизации YouTube, cookies, OAuth, player/download endpoints, извлечения аудио, прокси или обхода embed. Это не официальный YouTube Data API; возможность отказа/изменения схемы существенна. Ручной URL сохраняется как альтернативный путь. Поиск отправляет сервису названия и исполнителей подготавливаемых треков.

Запросы HTTPS, redirects запрещены, connect/total timeout 8/15 секунд, ответ до 3 МБ. Результаты: максимум 5 video ID + title/artist/score/reason. In-memory cache до 128 запросов: 1 час для найденных кандидатов, 30 секунд для пустых. Ограниченный рекурсивный parser, валидация video ID; не возвращаем сырые ответы в UI.

Ранжирование — консервативная эвристика: нормализованный title должен содержать все слова названия трека; одна artist credit должна точно совпасть с главным исполнителем источника (без регистра/диакритики). Каверы, реакции, karaoke, slowed/nightcore, tribute и чужие ремиксы исключаются. Законное название песни Cover Me не исключается только за слово Cover. Видеометка OMV усиливает score, но не является доказательством верифицированного официального канала. Live оригинального исполнителя допускается, длительность не ограничивает воспроизведение.

## Интеграция

Prefetch metadata для трёх ближайших треков. Результат привязан к source generation и ordinal: поздние ответы не меняют новую очередь, ручной URL не перезаписывается автоподбором. Готовый C не обгоняет неподготовленный B.

Первый клип только cue, без autoplay. После явного Play полное завершение видео продвигает очередь и продолжает воспроизведение; Next на паузе сохраняет паузу. При конце загруженной очереди запрашивается следующая source-порция. Pause во время поиска отменяет ожидающее продолжение. При embed error/timeout пробуется следующий candidate того же трека; если вариантов нет — ошибка и ручная ссылка, без скрытого пропуска композиции или фиктивного audio fallback. Кнопка «Подобрать заново» повторяет выбор; отрицательный кэш может действовать до 30 секунд.

## Доказательства

- Rust fixtures: официальный музыкальный video выигрывает у live при одинаковой релевантности; кавер/tribute/чужой artist/remix/не та песня отклоняются; диакритика нормализуется. Это небольшая проверка правил, не benchmark музыкального каталога.
- Реальный metadata spike: Oasis — Wonderwall, Coldplay — Yellow дают допустимых кандидатов. Запрос Кино — Группа крови успешно выполняется, но в наблюдаемой выдаче нет безопасного точного artist/title совпадения: другой трек и UGC отклонены. Пустой допустимый результат не считается отказом сети или успешным подбором.
- Native Windows, реальный аккаунт: source session/next batch PASS. Один запуск потребовал ручного выбора для текущей рекомендации; последующий запуск подтвердил source metadata → автоматический match → IFrame CUED без autoplay. Это отдельные новые сессии, не утверждение 100% покрытия.
- Native известный fixture: search Wonderwall/Oasis → найденный video → real IFrame cue PASS. Реальный Play/Pause/seek проверен отдельно на M7lc1UVf-VE, volume=0. Воспроизводимость всех найденных кандидатов и слышимость звука не доказаны.
- Renderer tests PASS: готовый C ждёт B, natural end продолжает после готовности B, Next на паузе не играет, Pause при pending search отменяет продолжение, embed failure меняет candidate внутри того же трека.

## Что остаётся

Региональные ограничения, rate-limit/backoff, разнообразный контрольный каталог/сложные версии и транслитерация, подтверждение оригинального канала, долгие сессии/сеть, настоящие embedded-error сценарии, Linux/macOS runtime, persistent favorites/TTL/override/history и audio fallback. Не объявлять S10 или непрерывный эфир полностью готовыми по этим ограниченным проверкам.
