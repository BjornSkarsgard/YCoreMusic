# Воспроизведение, синхронизация и аудио

## Временная модель
- Authoritative `playback_position_ms` = позиция **видео**; обновлять из активного плеера и экстраполировать при PLAYING по монотонным часам.
- `duration_ms` = длительность фактически выбранного видео, а не Yandex track; у live могут отличаться.
- При завершении **полного видео** перейти к следующему треку. Не пропускать интро/аутро.
- Seek из ПК/телефона/мультимедийных клавиш транслируется всем плеерам; после seek перепроверить позицию.

## Несколько плееров
- На каждом мониторе с видео отдельный IFrame; один выбранный `audio_authority`, остальные muted и volume=0.
- Координатор посылает PLAY/PAUSE/SEEK/LOAD c `generation` и временной меткой; измеряет drift, корректирует при превышении порога (предложение: 250–500 мс, уточнить spike).
- Не обещать синхронизацию по кадрам; разные задержки YouTube и throttling могут приводить к рассинхрону.
- Если аудиомонитор скрыт/отключён, звук должен продолжать работать из **стабильного единственного источника**, возможно отдельного headless/hidden audio authority; **SPIKE**, так как WebView2 может ограничить hidden playback.
- Перед передачей роли audio authority новому плееру гарантировать, что прежний muted; избегать двойного звука.

## Команды
`play`, `pause`, `toggle`, `next`, `previous`, `seek_absolute`, `seek_relative`, `set_volume`, `mute`, `set_repeat`, `set_output_device`.
- `previous`: первый → seek(0), второй за 3 с → предыдущая песня; paused-state сохраняется.
- `seek_relative`: стрелки ±5 с, clamp в диапазон [0,duration].
- `set_volume`: 0–100, сохранять, без изменения Windows master volume. Mute/unmute сохраняет прежнее значение.
- Никакой нормализации и никакого перекрытия звука при переходах.

## Аудиоустройство
- Список Windows output devices по стабильным endpoint IDs, сохранять выбранный ID и понятное имя.
- Не следовать за default device. Если endpoint пропал — **немедленно pause**; при возвращении оставить PAUSED и ждать Play.
- Маршрутизация WebView2-аудио на отдельный endpoint **не гарантирована** штатными API; проверить process audio routing и альтернативы. Не переключать звук на default молча.
- Если маршрут нельзя гарантировать — показать блокирующее сообщение/ограничение, не нарушать REQ-022.

## Визуализация звука
- Анализировать реальный звук **только приложения** до/независимо от UI volume, если возможно; отдельные Windows звуки не влияют.
- Захват WASAPI process loopback, FFT, envelopes/beat onset; отдавать нормализованные полосы и уровень по WS/IPC. При паузе мягкое затухание.
- WebView2 может порождать дочерние процессы, и audio routing/capture может не совпадать с основным PID: отдельный spike.

## Переходы
- Видео↔видео, видео↔визуализатор: Fade to Black 300–500 мс.
- Визуализатор↔визуализатор: Crossfade 500–800 мс, независимо по мониторам; при одинаковом preset не перезапускать анимацию.
- Аудио: **без crossfade**; в любой момент максимум один слышимый источник.

## Recovery
- Buffering >~5 с: пометить buffering и показать индикатор; >~15 с: попытка пересоздать IFrame и seek в сохранённую позицию. Пороги — ориентиры, тестировать.
- Каждая recovery-операция привязана к `playback_generation`; старые callback игнорируются.
- При потере сети **не** переключать композицию автоматически. Backoff и ожидание.
- При неработающем видео: другое избранное → другой кандидат → Yandex audio fallback (если доступен).
- Захват последнего кадра cross-origin не гарантирован: spinner на текущей поверхности.

## Windows SMTC и Power
- SMTC metadata title/artist, Play/Pause/Next/Previous, единая логика Previous.
- При PLAYING держать `SYSTEM_REQUIRED` и `DISPLAY_REQUIRED`; на PAUSED/STOP/Exit освобождать.
- Win+L не должен останавливать звук; после unlock resync сцен. Wake из сна — всегда PAUSED.

## Обновление по решению пользователя, 2026-11-03

Собственный выбор/закрепление output endpoint отменён. Раздел «Аудиоустройство» выше больше не задаёт обязательный lifecycle отключения/возврата: маршрутизацией и fallback управляет ОС. Сохраняются один источник, громкость приложения и no-autoplay на запуске/wake. S4 больше не является блокером.
