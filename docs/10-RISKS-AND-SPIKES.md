# Технические риски и обязательные прототипы

**Принцип:** пользователь утвердил желаемое поведение, но не доказал реализуемость внешних API. До полноценной разработки проверить каждый блокер на реальной Windows 11.

## Порядок экспериментов
**Gate A:** S1 + S3 — есть реальная музыка и клип. **Gate B:** S4 + S5 — можно гарантировать один звук и выбранное устройство. **Gate C:** S2 + S6 — fallback и честный аудиоанализ. **Gate D:** S7–S12 — мультиэкран, UX и эксплуатация.

## Как фиксировать результат spike
Для каждого: дата, Windows build, версии WebView2/Tauri/Python, тестовое оборудование, воспроизводимые шаги, скрин/лог без секретов, фактический результат, решение **PASS / FAIL / PARTIAL**, альтернативы и влияние на требования.

## Особенно важно
- YouTube IFrame API не гарантирует 1080p, точный FPS, отсутствие рекламы, получение пикселей последнего кадра или покадровую синхронизацию.
- Неофициальные библиотеки Яндекса и YouTube Music могут ломаться и иметь ограничения; не считать их стабильным официальным контрактом.
- Захват и маршрутизация аудио WebView2 зависят от дочерних процессов и Windows API; «установить громкость» не равно «выбрать устройство вывода».
- Нельзя маскировать отсутствующий Yandex audio fallback под извлечение аудио YouTube.
