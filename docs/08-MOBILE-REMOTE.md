# Мобильный пульт по локальной сети

## Модель
Телефон открывает responsive web UI по адресу локального сервера ПК (не отдельное нативное приложение). ПК по Ethernet и телефон по Wi-Fi в одной доступной LAN; не требовать одинакового физического интерфейса. Интернет не нужен для команд внутри LAN, но нужен для внешних музыкальных сервисов.

## Pairing
1. На ПК показать QR с локальным адресом и **одноразовым короткоживущим pairing code** (не постоянным токеном).
2. Телефон открывает страницу и запрашивает сопряжение.
3. ПК показывает название/параметры устройства и требует **явного подтверждения первого подключения**.
4. Сервер выдаёт отдельный revocable credential устройству, хранит только hash/защищённое представление.
5. При повторном подключении доверенное устройство входит без нового подтверждения; ПК позволяет отозвать доступ.
6. Несколько телефонов с **равными** правами; каждое действие отражается на всех.

## Функции
Play/Pause/Next/Previous, seek, volume/mute, repeat, like/dislike/Undo, выбор источника, queue, history, поиск, видео URL/избранные, мониторные сцены/визуализаторы/настройки, просмотр статусов устройства/сети.

## Sync
- Initial GET snapshot + WS stream `state_patch`/`event` с revision; после reconnect GET snapshot, не полагаться на пропущенные события.
- Команды имеют `command_id` и ack/error; сервер authoritative.
- Синхронизировать позицию с оценкой времени, не рассылать полное состояние 60 раз/сек.
- При двух одновременных командах применять серверный порядок; показывать последнее подтверждённое состояние.

## Security
- LAN endpoint bind только на выбранные частные интерфейсы; не открывать в Интернет, не использовать UPnP.
- Auth обязателен на **всех** REST/WS командах, кроме pairing bootstrap; rate limiting, Origin/CSRF safeguards.
- При доступе через HTTP в LAN bearer token может быть перехвачен: предпочтительно HTTPS с локальным сертификатом/доверенным механизмом; UX доверия сертификату — **открытый технический вопрос**. Не выдавать QR с долгоживущим токеном.
- Не возвращать Yandex OAuth token или системные секреты в API/логи.
- Доверенные устройства: имя, created_at, last_seen, revoke, rotate.
- QR и pairing endpoints с TTL, одноразовостью, лимитами попыток.

## Сценарии отказа
- Телефон сменил Wi-Fi: reconnect + snapshot; музыка на ПК не зависит от пульта.
- ПК ушёл в сон: соединение пропадает, после wake требуется ручной Play.
- Блокировка Win+L: пульт остаётся доступен, если сеть/сервер работают.
- Неизвестное устройство не может вызвать Play даже при знании IP.
