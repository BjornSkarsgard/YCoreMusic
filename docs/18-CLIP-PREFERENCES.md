# Предпочтение клипа и исключение видео

2026-11-05, REQ-063. В диалоге выбора клипа добавлены «Предпочитать этот клип» / «Снять предпочтение», «Не выбирать это видео» и список исключений с действием «Вернуть в подбор».

На песню приходится одно явное предпочтение. Оно выбирается первым, включая repeat-one; остальные избранные остаются запасными при недоступности. Пока явного предпочтения нет, сохраняется прежнее случайное чередование избранных без немедленного повтора. Снятие предпочтения возвращает это поведение. Выбор предпочтительного видео добавляет его в существующий набор избранных, не создавая отдельный параллельный список.

Исключение относится к конкретной паре track/video, не к артисту или песне целиком. Оно не отправляет музыкальный дизлайк в Яндекс. Исключение предпочтительного клипа снимает его приоритет, но не удаляет само избранное; удаление избранного также снимает его явное предпочтение. Отмена исключения разрешает автоподбор, но не восстанавливает прежний приоритет молча. Если исключён текущий клип, сохраняется текущая песня и play/pause intent, подбирается другое видео; событие замены — video_change. Если разрешённых вариантов нет, действует прежняя политика пропуска/ожидания источника. Ручная ссылка остаётся явным выбором на этот раз, исключения учитываются последующим автоматическим подбором/повтором.

Фильтр действует для избранного, history-кандидата, поиска, альтернатив и заранее подготовленной очереди. При изменении выбора очищаются запрещённые готовые позиции этой песни, а version guards отклоняют старые результаты поиска/чтения настроек. Удаление избранного само по себе не прерывает текущий клип. UI проверяет ключ позиции и video ID перед действием, блокирует повторные записи и показывает ошибки сохранения. Исключения доступны для отмены даже если подходящий клип пока не найден.

## Хранилище

SQLite schema6: `video_preferences` и `video_exclusions`; прежние favorites/manual/history/feedback/Wave таблицы сохраняются. До миграции существующего v1–v5 создаётся VACUUM backup; версия выше6 отклоняется с сохранением файла. Операции preferences/exclusions транзакционны и валидируют track/video IDs. Это локальные настройки, аккаунт и credentials не меняются. Кеш автоматических прочитанных политик ограничен1024 записями, версии изменяются при явных действиях пользователя.

## Проверки

- Rust64 PASS/9 ignored: scoped предпочтения/исключения, отсутствие изменений музыкальных реакций, удаление предпочтения, v5 backup и сохранение после открытия БД заново.
- TSunit13 PASS: старое случайное чередование и приоритет явного предпочтения при сохранении fallback.
- Targeted renderer: preferred repeat, замена видео без смены песни, Undo исключения, отсутствие Yandex dislike, фильтр history/автоподбора/альтернатив; прежние favorites/delete/Pause сценарии проходят.
- Полный renderer103 PASS/1 skipped после проверки пустого результата поиска старого bridge; исходное поведение сохранено.
- Native isolated SQLite command roundtrip preference→exclusion→restore PASS; полный single-host/multi-mirror/transport/tray/mini smoke после миграции PASS. Личный аккаунт и реакции не использовались.
- fmt/Clippy, TypeScript/Vite и Windows debug build PASS.

Личная музыкальная библиотека пользователя не мигрировалась тестами: новая обычная сборка применит миграцию при своём следующем запуске, предварительно создав backup. Сами тесты работали с временными/изолированными базами. Реальная сессия пользователя с новыми кнопками ещё не проверена; это отдельно от успешной нативной проверки IPC и renderer-интеграции.
