# ADR-032 — Выбор физического экрана по Windows monitor interface

2026-11-05, REQ029/031. monitor_list возвращает геометрию/DPI/primary из Tauri и Windows EnumDisplayDevicesW с EDD_GET_DEVICE_INTERFACE_NAME: DeviceID содержит имя интерфейса GUID_DEVINTERFACE_MONITOR, а не порядковый DISPLAYx. Путь остаётся native, IPC ID — явный FNV-1a64 от lowercase пути. Это идентичность устройства в текущей конфигурации Windows, не обещание неизменности при смене порта/драйвера. Неоднозначный cloned adapter и отсутствие platform identity помечаются stable=false; на Linux/macOS пока временный ID по name+position. Нельзя автоматически восстанавливать такую сцену по индексу/координатам как будто ID постоянный.

Основание: [Microsoft EnumDisplayDevicesW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumdisplaydevicesw). Номинальная частота берётся из EnumDisplaySettingsW.dmDisplayFrequency (целыеHz, не измерение фактического VSync). UI явно выбирает экран перед Open; missing ID отклоняется без создания/переноса на другой. Окно располагается по физической work area выбранного монитора с учётом DPI. На Windows native реально перечислены3 экрана/3 уникальных interface IDs/3 частоты; одно тестовое окно последовательно размещено на каждом из3, current_monitor проверен. Это не проверка HDMI отключения/возврата, сохранения конфигурации или трёх одновременных VIDEO.

# ADR-031 — Отдельное окно VIDEO как беззвучный подписчик

2026-11-05, первый срез REQ016/023/029/030/053. Окно video-scene содержит свой YouTube IFrame; основное окно остаётся единственным coordinator и audio authority. Native scene_publish принимает только ограниченный snapshot от main: generation/revision, videoId, title/artist, позиция/длительность, player state. Здесь нет токена, source refs, session/batch/account IDs. Новая сцена начинает с mute:1, на Ready и каждом StateChange принудительно mute+volume0. Нет unmute-пути; ENDED сцены не выбирает следующую запись. Snapshot каждые500ms, коррекция рассинхронизации более750ms при play /300ms при pause — рабочие внутренние параметры, не покадровая синхронизация.

Кнопки сцены передают ограниченные toggle/next/previous/seek в прежний main coordinator. Fullscreen/topmost действуют только на сцену. Нативные команды проверяют label; сцена не имеет доступа к credentials/storage/source/window configuration. Разрешён только локальный scene.html, новые браузерные окна запрещены. Асинхронное создание исключает блокировку WebView2 Windows; OFF дожидается удаления окна из native registry. Крестик скрывает окно, tray Open восстанавливает; скрытый/минимизированный follower уничтожает свой iframe и готовится заново при показе. Ошибка follower не переключает общую очередь; ограниченный retry дважды, без бесконечного восстановления.

Windows native-test: реальные два YouTube aqz-KE-bpKQ; follower действительно isMuted=true/getVolume=0, общая pause работает, скрытие main в трей сохраняет продвижение timeline6с, скрытие follower удаляет его iframe. Fullscreen/topmost/off и запрет main/storage команд из сцены проверены. **S5 PARTIAL**: тест общей громкости0, физическое отсутствие эха не измерялось; нет приёмки2–3 физических дисплеев, HDMI hotplug/long run. Этот срез создаёт одно дополнительное окно вручную, без привязки к монитору, persistence/hotplug, visualizer и передачи audio authority. Они остаются следующей работой; не выдавать окно за готовую полную мультимониторность.

# ADR-030 — Компоновка CONTROLS без смены воспроизведения

# ADR-001 — Переносимое приложение

Дата: 2026-11-03. Решение пользователя: Windows, Linux и macOS — целевые платформы.

Tauri 2 + TypeScript — экспериментальный shell. Общая музыкальная логика и контракты не зависят от ОС. Будущий backend — Python; в текущем каркасе отсутствует.

Платформенные адаптеры: endpoint routing/lifecycle, audio capture, media session, power management, secure credential storage, monitor identity. WASAPI/SMTC применимы только к Windows; Linux и macOS требуют отдельных исследований. Не подменять выбор endpoint системным default.

WebView2 (Windows), WebKitGTK (Linux), WKWebView (macOS) проверяются отдельно. Один успешный embed не доказывает другие платформы. Если Tauri не удовлетворяет обязательным требованиям, решение пересматривается после spike.

Исходное ТЗ описывает Windows 11. Новое требование пользователя расширяет платформы; остальные продуктовые инварианты сохраняются. Статус каждой ОС фиксируется отдельно.

## ADR-002 — Изолированный read-only probe Яндекса

Для S1 используем отдельную opt-in Rust CLI-утилиту с токеном только в памяти. Это позволяет проверить внешний API до реализации Python sidecar и защищённого постоянного хранилища. Утилита не является production source adapter, не принимает HTTP-команды от UI и не имеет общей playback state. Токен не попадает в frontend. Наличие legacy rotor не доказывает полный My Wave. Решение о production backend остаётся открытым до результатов spike.

### Уточнение ADR-002

Probe расширен до session API. Создание server session — отдельное действие на стороне сервиса; утилита больше не называется строго read-only в режиме по умолчанию. Не отправляет playback feedback. --legacy сохраняет первоначальный GET-only сценарий. Production-архитектура не изменена.

## ADR-003 — Вертикальный desktop-прототип без Python sidecar

Для проверяемого среза source → очередь → ручной клип используем Rust native source adapter и один TS PlaybackQueue. Native session.received хранит только список уже полученных ID для API prefetch, а не второй playback cursor. UI — один клиент/один плеер; мобильный пульт ещё отсутствует. Единственный cursor сейчас в TS, при добавлении нескольких окон/пульта его потребуется перенести в общий coordinator до выпуска этих функций.

Python sidecar остаётся архитектурным предложением, не реализованным компонентом. На этапе spike не добавляем второй транспорт и процессы ради простых source-запросов; тяжёлый синхронный HTTP/credential store выполняется через spawn_blocking, source операции сериализуются mutex. UI получает только метаданные, без token/session ID.

## ADR-004 — Постоянный секрет через хранилище ОС

CLI сохраняет токен только при явном --save-token после успешной авторизации. Desktop читает его из хранилища; Windows Credential Manager, macOS Keychain, Linux Secret Service выбраны явно через keyring 3.6.3 features. При недоступности хранилища — ошибка, без mock/plaintext fallback на поддерживаемых ОС. --forget-token удаляет только локальную запись. Windows OS store roundtrip проверен синтетическим credential с удалением, затем пользователь сохранил реальный token, native source fetch успешно его использовал. Linux/macOS пока не проверены аппаратно. Автоматическое получение/обновление токена и Device Flow остаются отдельной задачей.

## ADR-005 — Миниплеер в существующем окне

Меняем только layout и размер существующего native-окна. Тот же IFrame, тот же source/queue/cursor, без пересоздания и второго звука. Явный topmost через Tauri, без автофокуса; исходное положение/размер/maximized/fullscreen хранятся в памяти до выхода из mini. Нет сохранения этих параметров между полными запусками. Windows resize/restore, maximized roundtrip, системный topmost flag и single-instance guard подтверждены native WebDriver. Linux/macOS требуют проверки оконного менеджера.

## ADR-006 — Экспериментальный metadata search без отдельного Python процесса

S10 реализован небольшим Rust adapter по наблюдаемой публичной search-схеме YouTube Music. Перед интеграцией выполнен metadata spike; форма ответа проверяется и результаты консервативно фильтруются. Это эксперимент, не обещание стабильности неофициального API. Альтернатива — официальный YouTube Data API с отдельным ключом/квотами. Не добавляем Python interpreter только ради этого запроса; provider можно заменить за native command search_videos. Не запрашиваем медиа, авторизацию или обход ограничений. Ошибки и отсутствие безопасного совпадения оставляют трек текущим и ручной URL доступным.

## ADR-007 — Системная маршрутизация звука

Явное решение пользователя 2026-11-03: отдельный выбор выхода не нужен, управляет Windows. Используем системную маршрутизацию на desktop-платформах, без selector/sticky endpoint. REQ-022 superseded, S4 снят с обязательных gates. Незакоммиченный диагностический эксперимент удалён из кода; настройки Windows не изменялись. Один источник/громкость приложения/no-autoplay на запуске и wake сохраняются.

## ADR-008 — SQLite для ручных привязок и истории стартов

Сохраняем одну ручную video-привязку на трек и историю фактических стартов в нативном SQLite (rusqlite bundled), без нового sidecar. DB path задаётся через Tauri app_data_dir, данные отдельно от credential store. Полная история listened duration, source/reason, несколько избранных/random/no-repeat и действия Play Next/Append из истории ещё не реализованы. Это не завершение REQ-006/014 целиком.

playback_id идемпотентен на pause/resume. UI использует immutable metadata текущей загрузки, поздний результат запуска source не заменяет выбранную историю. Unknown/newer schema fail-closed без удаления. Тесты native UI запускаются с ENCORE_TEST_DATA_DIR только в debug-сборке, status.testMode проверяется перед записью/очисткой fixture. Личную БД тесты не меняют. Реальный пользовательский startup всегда создаёт новую My Wave-сессию без autoplay, история автоматически не возобновляется.

## ADR-009 — Канал не равен исполнителю; популярность подходящих кандидатов

Пользователь сообщил Living Dead Beat / Children Of Bodom и указал на ошибку сравнения канала с исполнителем. Убрано обязательное совпадение byline; UGC по заголовку группа+песня проходит независимо от канала. Playthrough/backing/instrumental, каверы и реакции фильтруются по названию, а не имени канала. Подходящие уверенные кандидаты сортируются по числу просмотров, score остаётся tie-break; нет обещания найти максимум по всему YouTube, сравниваем только полученную выдачу. Сомнительные варианты показаны отдельными кнопками для выбора. Регрессия по обезличенной публичной выдаче конкретного запроса сохранена fixture.

## ADR-010 — Каталог Яндекса и конечные очереди

Native catalogue adapter повторно использует защищённый API transport. UI получает только нормализованные metadata, IDs и owner UID для адресации публичного плейлиста. Search type=all, server correction включён; нет собственного словаря транслитерации. Просмотр отделён от выбора источника. Коллекции создают конечную очередь с контекстом pagination, источник Wave не подставляется по достижении её конца. Поздние source-init/search/collection результаты не могут заменить явно выбранную пользователем очередь.

## ADR-011 — Previous/repeat-one и несекретные volume preferences

У Previous монотонные часы performance.now и отдельный gesture state (3 секунды). Сейчас движение назад ограничено текущей очередью; cross-source playback stack ещё отсутствует. Repeat-one пересоздаёт цикл того же клипа, пишет отдельный history event после фактического Play. Несколько favourite-вариантов/random/no-repeat и repeat-queue ещё не реализованы.

Volume/mute — JSON под ключом encore.volume.v1 в origin-localStorage WebView. Это UI-предпочтения без credentials; OAuth туда не попадает. Некорректные/недоступные preferences не препятствуют запуску, ошибка записи видима. Default 50%, full launch не запускает музыку независимо от сохранённых настроек. Native smoke сохраняет/восстанавливает исходную volume preference, чтобы временный volume=0 не оставался у пользователя.


## ADR-012 — Трей, системные media controls и sleep/wake

CloseRequested скрывает окно только при успешно созданном трее; без трея остаётся обычное закрытие. Open/повторный запуск показывают прежнее окно, снимают minimize и сохраняют сессию. Выход — отдельное действие app.exit, без перехвата OS shutdown. Tray Play/Pause, SMTC/MPRIS/Now Playing отправляют команды существующему TS-координатору, без global keyboard hook или второй очереди.

Souvlaki 0.9.3 владеет native media controls на Tauri event-loop thread (thread_local, важно для macOS). Метаданные/состояние публикуются из реальных IFrame событий; progress обновляется раз в 2 секунды, revision отсекает поздние сообщения. На Windows Chromium HardwareMediaKeyHandling выключен, чтобы собственный обработчик WebView не дублировал SMTC. См. [API Souvlaki](https://docs.rs/souvlaki/0.9.3/souvlaki/).

Sleep/wake наблюдает tauri-plugin-power-monitor 0.1.0 ([API](https://docs.rs/tauri-plugin-power-monitor/0.1.0/tauri_plugin_power_monitor/)). Suspend/resume отменяют play intent, сохраняют очередь и позицию без новой Wave-сессии. До явного Play поздний PLAYING снова ставится на паузу. Возможен отказ OS listener; реальный sleep и аппаратные медиаклавиши требуют ручной проверки. Linux зависит от logind, альтернативные окружения ещё не проверены.

На Windows во время фактического PLAYING применяется thread-local SetThreadExecutionState SYSTEM_REQUIRED + DISPLAY_REQUIRED; пауза, suspend/resume и полный Exit снимают запрос. Ручной сон/lock не блокируются. Linux/macOS idle inhibition ещё не реализован. Native smoke имитирует события suspend/resume, не усыпляет компьютер и не выдаёт этот результат за аппаратную проверку.

Две macOS arm64 CI jobs не получили hosted runner из-за capacity constraints, без запуска шагов. Добавлен независимый macos-15-intel; arm64 job сохранён. [Доступные стандартные labels GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).


## ADR-013 — Вставка истории без смены источника

History Next/Append добавляют сохранённый video ID, не меняют текущий player/play intent и сохраняют исходный режим Wave/конечной коллекции. Без source queue активный manual video становится первым элементом конечной очереди; без активного видео история подготавливается paused. ordinal теперь стабильный ID элемента внутри generation, а позиция хранится cursor отдельно: вставка не переназначает поздний match на другой трек. Для ahead/end используются явные методы очереди, не арифметика ordinal.

Дополнительно revision-фильтр media update вынесен перед power request, чтобы отсутствие media backend не позволяло старому PLAYING задержать снятие idle inhibition.

## ADR-014 — Локальная macOS-поправка power-monitor 0.1.0

CI выявил native link failure _IOPSRelease в зависимости. Минимальный vendor patch сохраняет upstream 0.1.0 и лицензии, удаляет отсутствующую FFI-функцию и использует CFType create-rule RAII для CFRelease snapshot. [Apple указывает CFRelease для результата IOPSCopyPowerSourcesInfo](https://developer.apple.com/documentation/iokit/1523839-iopscopypowersourcesinfo). Cargo patch лежит в src-tauri/Cargo.toml; происхождение и условие удаления описаны в vendor/tauri-plugin-power-monitor/ENCORE-PATCH.md. Это не отключение sleep/wake на macOS.


## ADR-015 — Repeat queue и изолированный native профиль

Repeat queue разрешён только finiteSource. Повтор начинается после последней загруженной страницы коллекции, использует ту же очередь/клип и новый play-event при фактическом старте; paused Next через конец остаётся paused. Новая Wave-сессия сбрасывает queue-repeat в off. Локальные Space и стрелки действуют в текущем WebView, пропускают editable/button/link/dialog targets и модификаторы; global keyboard hook отсутствует.

Профиль Cargo native-test наследует dev и собирается в отдельный output, поэтому работающий пользовательский encore.exe больше не блокирует native smoke. Только debug + ENCORE_TEST_DATA_DIR заменяет config identifier на io.encore.desktop.test до создания приложения. Изолированы single-instance lock и WebView preferences; OS credential service остаётся прежним для разрешённых read-only live probes. Вторая тестовая копия получает тот же test env. Обычный пользовательский запуск и release не меняют identity. Native smoke рядом с работающим пользовательским PID прошёл, тестовый экземпляр завершился сам.


## ADR-016 — Своя панель и отсутствие hover UI

По запросу пользователя controls=0, fs=0, disablekb=1; native iframe pointer-events:none и tabindex=-1 в обычном режиме. Основные controls/timeline/CC/fullscreen находятся за пределами видео. Никакого обрезания содержимого, накладных масок или извлечения stream URLs. По явному действию «Панель YouTube» controls=1 и pointer-events:auto временно возвращаются для качества. Этот переход пересоздаёт один IFrame с прежней позицией/play intent и тем же playback record, не пишет новый старт истории; поздние callbacks отсекаются generation.

Программное setPlaybackQuality является no-op: [официальная история изменений](https://developers.google.com/youtube/iframe_api_revision_history). Поэтому отдельного фиктивного списка 1080p/720p нет; качество показывает onPlaybackQualityChange, ручной выбор выполняется в YouTube. После скрытия native панели выбранное качество может сброситься. [Параметры showinfo/modestbranding больше не скрывают служебный UI](https://developers.google.com/youtube/player_parameters); пауза/загрузка не обещают полностью пустого кадра.

CC track/tracklist берутся только при наличии этих runtime options; fontSize/reload описаны в [официальном API](https://developers.google.com/youtube/iframe_api_reference#Events). Track/loadModule/unloadModule остаются экспериментальным runtime bridge. getOption(track) сохраняет последнюю дорожку даже при off, поэтому селектор хранит явный выбор. YouTube включает CC при muted Play; каждый PLAYING повторно применяет выбор, onApiChange повторяет off с коротким ограничением частоты, предотвращающим feedback loop. Native smoke проверяет реальный caption state в тестовом iframe, а не только текст нашего селектора. Отсутствие CC API не мешает основному воспроизведению.

## ADR-017 — Личная медиатека, реакции и обновляемый обзор

REQ-002: аккаунт определяется нативно через account/status с OAuth из OS store. Медиатека объединяет собственные и сохранённые плейлисты, любимые ID загружаются из users/{uid}/likes/tracks. Метаданные страниц по 100 получаются POST /tracks с form track-ids, затем восстанавливается исходный порядок, включая недоступные элементы и повторы. OAuth не передаётся в UI. Чарт читается из landing3/chart, редакционные подборки из landing3; не выдаём подборки за ранжированный список популярных, если API его не предоставил. Обновление — явная кнопка, порядок сервера сохраняется.

REQ-008/009: SQLite v2 добавляет track_feedback с ключом (account_id,track_id), state -1/0/1, revision и pending. Pending-строки являются постоянным coalescing outbox: на один трек хранится последнее желаемое состояние, а не последовательность лишних запросов. ACK сбрасывает pending только при совпадении revision; ошибка оставляет его для следующей попытки. Отдельный аккаунт не получает чужой outbox. Перед отправкой сверяется реальный uid токена. Добавление like/dislike использует соответствующий add-multiple, нейтральное состояние снимает обе отметки; подтверждение требует result.revision. Протокол: [исходники адаптера likes](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client/likes.py).

Перед миграцией существующей v1 создаётся согласованный SQLite snapshot через VACUUM INTO, затем транзакционная миграция без изменения history/manual_videos. Backup v1 проверен отдельным тестом. Неизвестные и более новые схемы по-прежнему отклоняются. Дизлайк переключает сразу, Undo доступен 5 секунд и возвращает прежнее желаемое состояние только для своей revision; текущую композицию назад не возвращает. UI отслеживает внешние изменения периодическим чтением/обновлением.

Native test mode запрещает реальные feedback-записи. Read-only личная медиатека проверена на настоящем аккаунте; доставка реакций проверена через подменённый транспорт, сохранение/повтор/Undo — UI и SQLite tests. Реальный успешный write с текущим токеном ещё не проверен: тесты не меняют музыкальные предпочтения пользователя. Работа кнопок вызывает реальную запись только по явным действиям пользователя или доставке их сохранённого outbox.

## ADR-018 — Видимые альтернативные видеоклипы

По прямому запросу рядом с плеером постоянно доступен блок альтернатив: превью i.ytimg.com, исходное название YouTube, просмотры и durationSeconds из публичных поисковых метаданных. Нет запросов media/download/player stream. CSP разрешает картинки только self и i.ytimg.com. Неизвестные просмотры/длительность подписаны явно, не подменяются нулями. Выбор сохраняет queue cursor и play/pause, начинает другое видео той же композиции, заменяет единственный IFrame с generation guard и записывает ручную привязку. Для сохранённого клипа старт не ждёт дополнительного поиска: альтернативы подгружаются отдельно в общем лимите трёх поисков. Ранжирование остаётся по просмотрам среди релевантных, пользователь может предпочесть официальный клип live-версии. Несколько избранных и random/no-repeat из REQ-014 — следующий самостоятельный срез, пока сохраняется одна привязка.

## ADR-019 — Несколько избранных клипов и фактически сыгранное видео

REQ-014: SQLite v3 добавляет video_favorites(track_id,video_id,added_at,unavailable_at) и video_play_state(track_id,video_id). При обновлении из v1/v2 создаётся SQLite backup соответствующей версии; прежняя manual_videos привязка переносится в набор избранных. Legacy-таблица остаётся для совместимости IPC, но основной UI читает полный набор.

Выбор выполняется при переходе к текущему элементу, не во время prefetch: Fisher–Yates shuffle и исключение предыдущего из первой позиции при >=2. Предыдущее означает фактический PLAYING, сохраняется при записи history и учитывается после перезапуска. Это предотвращает влияние заранее подготовленных повторов трека на текущий repeat-one. При повторе перечитывается актуальный набор, соблюдаются generation и текущее play intent. Позднее чтение не включает музыку после Pause.

Звезда «Клип» сохраняет/удаляет текущий вариант. Диалог показывает все избранные с отдельным удалением и ручным повтором недоступного; удаление текущего не прерывает его воспроизведение и не удаляет историю. «Автоподбор на этот раз» обходит набор только для текущего элемента, не стирает сохранённое. Подтверждённые YouTube errors 2/100/101/150 помечают избранное недоступным, не удаляют; успешный PLAYING снимает пометку. Автоматический выбор временно исключает помеченные варианты до ручной успешной проверки; fallback продолжает другие избранные/поиск в существующем ограниченном бюджете. В My Wave нет подмены потока видео аудиодорожкой.

Проверки: v1 и v2 migration backup/preservation, несколько ссылок/duplicate add/unavailable/restart/last actual video, pure shuffle, renderer 6 повторов/удаление/late Pause/fallback. Настоящий Windows native: два проверенных Oasis видео чередуются по реальному END в repeat-one; снятие звезды оставляет воспроизведение. Только изолированная тестовая SQLite, volume=0.

## ADR-020 — Локальная Smart History как источник восстановления

REQ-005/007: при отказе Wave используется уже загруженная очередь; после её исчерпания (или неудачного старта) выбирается локальная Smart History. Источник не возвращается в Wave сам при восстановлении API. Явная кнопка в истории запускает его отдельно; Wave включается вручную. Пустая история сообщается без фиктивных треков и без запуска старой cue.

Native читает до 500 уникальных записей с последними title/artist/video ID, частотой и временем. Известные дизлайки, включая pending local intents, исключаются; cached профиль аккаунта берётся без сетевого запроса/ожидания network mutex. При отсутствии профиля применяется консервативное исключение известных локальных отрицательных состояний. Выбор с весами выполняется единственным TS coordinator. Техническая формула: 1 + ln(plays+1) + 4 за like + 2/(1+ageDays/7); это реализация, не новая утверждённая пользователем формула вкуса. Не повторяется предыдущий track при >=2 кандидатах.

Сначала используются сохранённые favourites, затем ранее сыгранный video ID; подбор метаданных не блокирует рабочий известный клип. Ошибки и отсутствие подходящих вариантов не записывают dislike. Исчерпанные варианты временно исключают композицию из текущей локальной подборки; явный повторный запуск/новый favourite/успешный Play разрешают проверку снова. Непоисковый старый manual clip с пустым artist после ошибки пропускается, а не маскируется под вечный network retry.

Generation/intent guards защищают смену источника и поздний ответ после Pause/wake. Даже pending старт локального источника имеет доступную Pause. Серверные snapshots реакций передаются только при отсутствии pending outbox; generation отклоняет старое чтение после нового Set, pending локальные действия перекрывают snapshot. Внешнее снятие дизлайка возвращает eligibility. OAuth/account UID по-прежнему не передаются в UI.

Порог quick-skip Q06 не утверждён, классификация и listened_ms/end_reason пока не реализованы. Частота основана на фактических стартах. Cold-offline новый feedback требует ранее установленной в текущем запуске идентичности аккаунта; уже сохранённый outbox переживает перезапуск и доставляется после соединения. Это остаётся следующим улучшением, а не обещанной полной offline identity cache.

## ADR-021 — История с курсором по фактическому событию

REQ-006: browsing history больше не ограничен одним списком последних100. Нативная команда storage/history сохраняет массив в ответе и принимает необязательный beforeId (положительный ID события); старые клиенты без курсора продолжают получать первую страницу. SQL id<beforeId, ORDER BY id DESC, LIMIT100 сохраняет повторные прослушивания и исключает смещение страниц из-за новых записей. Миграция БД не требуется. Поиск case-insensitive по существующему нормализованному search_text применяется к каждой странице.

History UI вынесен из playback coordinator в отдельный history-ui, принимает только callbacks now/next/append. Владелец очереди прежний. Дозагрузка добавляет DOM строки, новая выдача заменяет их. Ввод немедленно отменяет revision и блокирует старые действия на время debounce/request. Старый ответ, включая до очистки, не возвращает записи в интерфейс. При ошибке можно повторить страницу с прежним курсором. На ровно100 последних записях следующая пустая страница завершает пагинацию.

Очистка остаётся с подтверждением. Повторная команда заблокирована до ответа; ошибка видна внутри модального диалога и допускает retry. Избранные видео и текущая очередь не очищаются. UI показывает title/artist/date раздельно.

## ADR-022 — Восстановление того же клипа и подтверждённый offline

REQ-046: после15с buffering восстанавливаем тот же IFrame на последней известной позиции с тем же фактическим playback record. Не добавляем историю за техническое пересоздание. Повтор через2/4с; далее backoff до30с. В Wave после двух неудачных восстановлений разрешён прежний подбор альтернатив; конечный список вне fullscreen продолжает тот же clip с backoff, очередь не теряется.

Browser offline — подтверждённый сигнал недоступности: не очищаем video ID, не помечаем favourites unavailable, не пропускаем треки, не начинаем предзагрузку. Уже буферизованное видео может доиграть. END ждёт reconnect, затем учитывает repeat-one/обычное продолжение. Явный Next пользователя сохраняет право сменить трек. Online восстанавливает только сохранённый play intent; Pause/wake не запускают музыку. Timer связан с player generation, source revision, queue generation и intent revision; смена клипа/источника отменяет его.

navigator.onLine не доказывает доступность конкретного сервиса: при online+ошибке YouTube ограниченный recovery/fallback сохраняется. Системную сеть пользователя не меняем. Реальные preference writes не нужны для этих проверок.

## ADR-023 — Опциональный автозапуск и отдельный путь старта в трей

REQ-043 реализуется официальным tauri-plugin-autostart2.7.0 (https://v2.tauri.app/plugin/autostart/), только через собственные main-window commands. Плагину не выданы guest permissions: remote iframe не может менять автозапуск. Инициализация ничего не регистрирует; enable/disable вызывается только checkbox пользователя. Состояние читается и подтверждается ОС, в localStorage не дублируется. При ошибке UI предлагает перечитать, не утверждает, что изменение точно отменено.

Системная запись передаёт только --encore-autostart. Такой полный запуск скрывает окно до его показа, создаёт новую Wave сессию без autoplay. Если трей не создался, окно показывается, чтобы приложение не потерялось. Повторный фоновый запуск не фокусирует существующий экземпляр; обычный второй запуск восстанавливает окно. Mac Launcher выбирается только в cfgmacos, Linux/Windows используют собственный механизм плагина.

Test profile использует имя Encore Native Test и запрещает системные enable/disable в native command. Native smoke читает состояние и проверяет отказ мутации; запуск аргументом можно проверять без регистрации через ENCORE_AUTOSTART_SMOKE=1. Это не заменяет проверку настоящего входа в ОС или регистрации пользователем. Сборка/renderer/unit проверки ниже, runtime приёмка ещё ожидается до завершения часового Wave прогона.

## ADR-024 — Сохранение реакций не ждёт сети

REQ-008/009: HTTP-чтение/доставка больше не держат mutex профиля. Отдельные refresh/sync guards последовательно обслуживают сетевые операции; короткая cache lock защищает локальную транзакцию и generation. Старый refresh не применяет профиль после нового Set/sync. Record и generation выдаются атомарно под одной блокировкой. При синхронизации аккаунт по-прежнему заново определяется по текущим credentials, ACK защищён revision.

Профиль накладывает все pending intentions текущего account, без ограничения25 элементов транспортного batch; отправка остаётся батчами25. Устаревший offline cache не выдаётся как полный свежий snapshot исключений. UI оставляет известные реакции текущего трека доступными во время remote refresh, блокирует только его незавершённый Set, принимает локальный ACK несмотря на параллельный refresh и откатывает optimistic state при ошибке записи.

Проверки включают реальный interleaving двух потоков доставки и нового Set: отправлено oldlike затем newdislike, старая ACK не удаляет новое намерение. Отдельно pending60, account isolation, stale refresh и UI local success/failure при pending Get. Это не сохраняет identity нового cold-offline запуска: первоначальное определение аккаунта остаётся обязательным. Реальные музыкальные предпочтения для тестов не менялись.

## ADR-025 — Вход Яндекса в отдельном нативном окне

2026-11-05. Порядок работ уточнён пользователем: вход → интеграция Яндекса → сцены/визуализаторы/пульт; Linux/macOS приёмку отложить до конца, сохранять переносимую архитектуру.

Device Flow проверен без пользовательского подтверждения: /device/code отвечает200, обмен текущего client_id без client_secret — invalid_client. Секрет чужого OAuth-приложения не добываем и не встраиваем. Используем существующий implicit OAuth client_id и зарегистрированный HTTPS callback https://music.yandex.ru/ (без переопределения redirect_uri). Отдельное incognito WebView-окно без native capabilities, HTTPS navigation только доменов Яндекса, новые окна запрещены. Callback перехватывается до отрисовки нативно: точный origin/path, случайный256бит state, однократный результат,10мин срок, cancel/generation guards. Токен не возвращается в IPC/DOM/logs/SQLite; account/status проверяется до замены OS credential. Ошибка/отмена сохраняет прежний credential. Проверка нового токена readonly; тестовый профиль не сохраняет/не удаляет реальные credentials.

Окно входа использует отдельный cache profile и те же browser arguments, что main: иначе WebView2/автоматизация возвращает HRESULT8007139F из-за несовместимых environment options. Закрытие в трей применяется только к main. Явный disconnect подтверждается в UI, удаляет только локальный credential; это не глобальный отзыв Яндекс-сессий. Pending reactions остаются account-scoped, кеш инвалидируется с generation; успешный вход/выход обновляет frontend без autoplay.

Ограничения: фактическое получение нового токена после пользовательского подтверждения и закрытие окна крестиком требуют живой проверки. Windows native открытие/отмена кнопкой/удаление окна и testMode mutation guard PASS; WebDriver DELETE window закрывает browser target и не заменяет проверку OS-крестика. Начальный login popup относится к интеграции, не к дополнительной музыкальной сцене.

## ADR-026 — Публичный каталог и персональные операции разделены

2026-11-05. По REQ052 гостевой поиск/исполнители/альбомы/публичные плейлисты/чарт используют native public_request с optional sensitive auth header и fallback без него только при authdenied. Никаких guest credentials или чужих аккаунтов. В public_request whitelist GET endpoints; account/session/personal feedback не проходят. Секреты по-прежнему native/OS-store. Публичные запросы могут работать даже при ошибке credential store, но такая ошибка сохраняется в диагностике аккаунта.

Чарт — обязательный результат discovery, editorial landing — optional с флагом playlistsAvailable; ошибка отдельного блока не отменяет чарт. Гостевой landing публичную проверку не прошёл (400), поэтому подборки доступны через публичный поиск, а не выдуманные редакторские данные. Приватный playlist не раскрывается без разрешения Яндекса. ## ADR-027 — Наблюдаемое прослушивание отделено от позиции видео

2026-11-05, REQ006/007 и основа S1 playback lifecycle. ListeningMeter использует monotonic wall clock и наблюдаемое продвижение видео только при PLAYING; pause/buffering/seek не увеличивают listening. Известные seek явно меняют опорную позицию; большие неизвестные скачки таймлайна не считаются прослушиванием. Скрытое продолжающееся видео учитывается. Quality/recovery reload сохраняет прежний play event и счётчик; новый фактический старт после END/repeat создаёт новый ID.

SQLitev4 добавляет отдельную play_metrics с source/listened_ms/duration_ms/end_reason/ended_at. duration_ms относится к полному YouTubeвидео, не к длительности Яндекс-аудиозаписи. Перед v1/v2/v3 upgrade VACUUM INTO backup; старые записи не получают выдуманного времени. Пишем последовательные watermark checkpoints раз в5с и при смене состояния, не повторяем неизменный payload. SQL MAX защищает от позднего меньшего checkpoint; первая терминальная причина сохраняется. Метрика создаётся только для существующего play_history; clear удаляет обе таблицы транзакционно, поздний progress не восстанавливает историю. При обычном native Exit незавершённые сохранённые события получают shutdown; при следующем открытии остатки после аварии — interrupted. Аварийное завершение может потерять последний неперсистированный интервал до5с, iframe timing является наблюдением, не гарантированным аудиоизмерением.

Причины: natural/skip/dislike/error/source_change/video_change/shutdown. Technical error и dislike различны; Q06 не применялся, автоматических quick-skip исключений не добавляли. Пока это локальная история: отправка session feedback Яндексу требует отдельного среза с привязкой к действительной session/batch/account и проверкой. Тесты не отправляют искусственных прослушиваний в пользовательские рекомендации.

## ADR-028 — Session feedback с native origin и отдельной очередью доставки

2026-11-05, S1/REQ002/003/008. Каждая реально выданная запись Wave получает собственный случайный128бит waveRef, включая одинаковые trackID. Native registry4096 хранит account/session/batch/track; наружу идут только id/title/artist/waveRef. Account/status проверяется при fetch; смена UID требует fresh session. При renewal старые refs сохраняют старуюsession/batch и не перепривязываются к последней порции.

SQLitev5 добавляет wave_events (backup перед v1–v4 upgrade). При первом actual PLAYING создаются radioStarted один раз наsession и trackStarted наplaybackID; завершение даёт trackFinished с наблюдаемыми totalPlayedSeconds, только явный Next — skip. Technical error не становится skip/dislike. Library reactions — прежняя отдельная синхронизация: дополнительный recommendation-dislike не дублируется, чтобы Undo не оставлял отдельный неотменённый негатив. Для ручной смены версии/технического окончания отправляется нейтральный trackFinished; повторное фактическое начало имеет новый playbackID. Cue/pause/buffering не создают starts. SDK-contract: MarshalX yandex-music-api `_client/rotor_sessions.py`, `rotor/session_event.py`, `rotor/session_feedback.py`.

Outbox account-scoped, session/batch сохраняются native. Event keys дедуплицируют локальные повторные checkpoints; sent receipts остаются, чтобы не отправлять заново по следующему progress. Сетевой worker не держитSQLitelock; проверяет текущий credential перед каждым запросом и не доставляет outbox чужого UID. Retry/backoff, максимум8 попыток,24часа TTL; истёкшее событие не пересаживается на новуюsession. Подтверждение — HTTP/JSONresultobject безunknownSession/terminated. Это локальная дедупликация: если ответ потерян после приёма сервером, удалённый exactly-once не гарантируется.

Общий frontend historyWriter сохраняет порядок окончания старого и начала новогоevent. Clear дожидается текущих локальных записей, транзакционно удаляет Waveevents с историей, а worker проверяет наличие следующей pendingстроки после сетевого ответа. In-flight запрос уже нельзя отозвать. При normalExit native добавляет окончание по последнему сохранённому watermark, затем закрываетmetrics; аварийное восстановление не выдумывает новый start. В testMode wave_sync возвращает disabled до чтения credentials/любых внешних writes.

Реальная проверка: пользователь сообщил успешную отправку, readonlyагрегат normalAppData v5 показал sent radioStarted2/trackStarted5/skip3/trackFinished1 и0pending. Личность/track/session/token не извлекались в вывод. Все события — обычные действия пользователя, не тестовые проигрывания. Пользователь дополнительно подтвердил реальный like Encore→приложениеЯндекса. Обратное ручное изменение лайка и realdislike/Undo вЯндексе остаются отдельнойприёмкой, не объявлены завершёнными.

## ADR-029 — Выбор стабильной позиции очереди и подгрузка метаданных

2026-11-05, REQ054/055. Queue.select выбирает ordinal с проверкой generation; это единственный прежний coordinator/cursor, не новая очередь. Ручной переход перемещает курсор, сохраняет порядок и видимые предыдущие позиции. Следующий трек идёт после выбранного. Дубликаты trackID различаются ordinal. Только реально оставленный игравший трек получает skip; непрослушанные промежуточные записи не порождают events.

Отдельные navigation/advanceOwner отменяют позднее продвижение после ручного выбора/Previous; фоновые порции при этом остаются в прежней очереди, если source generation не сменился. DOM обновляется после прежнего trimPast50, поэтому не показывает кнопки уже удалённых из rollingbuffer записей. Ручной jump сам предыдущие записи не удаляет. Предел rollingpast50 сохраняется с прежней реализации; это не бесконечный архив очереди.

queue-scroll следит только за видимой Wave-очередью и общим scrollpane, порог120px. Работает поверх существующего sourceWork, не выбирает клип и не меняет playIntent. Заполняет короткий viewport, сохраняет numeric scroll и keyboard focus, блокирует повторный автозапрос после ошибки до retry/успешного обновления. Буфер следующих записей ограничен примерно500 плюс последняя порция, чтобы бесконечная прокрутка не съедала память; подгрузка возобновляется по мере продвижения. Архив слушаний по-прежнему в History.

Реакция текущего трека перечитывается при возврате фокуса: debounce250ms/min3s, без новых Set. Mock-проверка показывает внешнее добавление/снятие лайка без writes; реальное обратное изменение ещё не подтверждено человеком.
