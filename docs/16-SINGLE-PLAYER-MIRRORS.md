# Один плеер и управление экранами

2026-11-05, REQ-056/057. Заменяет прежние muted follower окна. Основное окно сохраняет единственную очередь и coordinator. На Windows единственный настоящий YouTube IFrame живёт в техническом окне `player-host`, а основное окно и дополнительные экраны показывают локальные DWM thumbnails. Повторной загрузки видео/декодирования для каждого экрана нет.

## Пользовательский сценарий

Кнопка **Экраны** находится в верхней панели основного окна, также доступна из настроек. Диалог предлагает выбрать монитор и содержимое. Для клипа можно включить отдельное окно на каждом подключённом мониторе; включение другого экрана не переносит уже открытое окно. «Выключить окно» относится только к выбранному экрану. Можно оставить основное окно в режиме «Только управление».

Нет искусственного ограничения числа экранов: по одному окну клипа на подключённый монитор. Фактическая производительность на большом числе экранов не измерена. Визуализаторы пока недоступны: реальный захват/анализ звука S6 ещё не проверен. Это явная граница реализации, а не имитация аудиореактивности. Hotplug и сохранение сцен между запусками — следующие задачи.

Диалог требует явного выбора монитора, блокирует запуск при ошибке списка или исчезновении выбранного экрана. Кнопки действия закреплены, шаги прокручиваются на небольшом окне. Esc/крестик возвращают фокус. Телевизор должен быть доступен ОС как монитор; прямой Chromecast/AirPlay/casting не добавлен.

## Архитектура

- `host-engine.ts` / `player-host.html`: один YouTube IFrame; cue без autoplay, реальные position/state/captions/quality, bounded отчёты состояния. Нет доступа к аккаунту, credentials, источникам рекомендаций или SQLite.
- `player-host.ts`: фасад прежнего интерфейса YT.Player, кеш реального состояния и последовательная отправка transport-команд. Поздние поколения и пакеты с меньшим sequence игнорируются. Новая загрузка не допускает одновременно два IFrame.
- `player_host.rs`: роли main/source/scene, проверенные команды, поколения, сериализация загрузок, отдельный browser profile источника. Capability источника разрешает только приём событий.
- `video_mirror.rs` / `video-mirror.ts`: локальная поверхность DWM без YouTube/network player. DPI/aspect/letterbox, вырезы для HTML диалогов и fullscreen HUD, ослабление яркости под модальным окном. Нет копирования кадров через JS и постоянного screenshot-loop.
- `scenes.rs`: независимые окна, привязанные к проверенному monitor ID; создание/выключение сериализованы. Каждая сцена может управлять общей сессией, но не создавать свою очередь. SceneOff снимает DWM handles. Закрытие скрывает только свою сцену; повторный показ не пересоздаёт engine.

Технический источник остаётся OS-visible, но alpha0, click-through, no-activate, skip-taskbar: настоящий hide останавливает отрисовку на проверенной системе. Панель YouTube для ручного качества временно показывает этот же источник. При закрытии он возвращается в прозрачный режим. Изменение native alpha выполняется на UI thread после Tauri/Tao setters: иначе оформление окна может сбросить layered attributes.

Общие WebView2 browser arguments совпадают. Разрешение browser-level autoplay нужно для команды Play через IPC; application-level play intent, cue и wake guards сохраняют отсутствие автоматического старта.

## Платформы и проверка

Windows DWM engine включён в default feature `single-player-host`. На Linux/macOS основной плеер остаётся внутри приложения; дополнительные локальные зеркала требуют собственного платформенного механизма и сейчас не доступны. Это не отказ от поддержки этих ОС и не утверждение, что Tauri автоматически переносит DWM. Проверка только сборки недостаточна для полной поддержки.

Windows native проверка выполнена на Windows 10 build 19045, с тремя подключёнными дисплеями. Подтверждены два дополнительных окна на разных мониторах, меняющиеся реальные пиксели второго зеркала, один source IFrame и ноль IFrame в main/scene, отсутствие autoplay, play/pause/seek, панель качества, реальный HTML dialog/fullscreen HUD над зеркалом, CONTROLS, tray, общий Pause, targeted Off, mini/restore/topmost/single-instance. Тестовый звук volume0; физическое прослушивание и производительность часами не объявлены проверенными. Тестовый ролик не предложил CC: реальный on/off CC в этом прогоне не утверждается, протокол языка/размера покрыт renderer-проверкой.

Полный renderer: 100 PASS, 1 skipped. Rust: 60 PASS, 9 opt-in ignored; fmt и Clippy PASS. Нет новых dependencies. Для повторения из корня:

```powershell
npm.cmd run build --prefix apps/desktop
cargo build --manifest-path apps/desktop/src-tauri/Cargo.toml --profile native-test --features tauri/custom-protocol,mirror-probe --bin YCoreMusic
$env:YCORE_SINGLE_HOST_SMOKE='1'
node scripts/native-smoke.mjs
```

Native тест использует только изолированный testMode и не читает/не меняет личные credentials или рекомендации. Pixel probe ограничен собственными окнами и перед чтением проверяет, что область не перекрыта другим приложением; целевой scene label проверяется. При перекрытии отказывается от захвата. Снимки и тестовые профили не коммитятся.

Сохранённый stash до переименования оставлен как историческая страховка; применять его повторно не нужно. Реализация перенесена выборочно и адаптирована к новому брендингу/теме. Ограничения: ещё нет hotplug/persistence, визуализаторов, проверки physical sleep/lock, полной аппаратной приёмки Windows11/Linux/macOS и benchmark большого количества экранов.
