# Согласованные продуктовые решения (source of truth)

Условные метки: **REQ** — обязательное согласованное поведение; **SPIKE** — желаемое поведение, технически не подтверждено; **PROPOSAL** — технический вариант реализации.

## Продукт и источники
- **REQ-001** Windows 11 desktop, установка, ярлык, трей; запуск не запускает музыку автоматически.
- **REQ-002** Основной режим — «Моя волна» Яндекс Музыки; также понравившиеся треки, плейлисты, альбомы, исполнители, поиск, ручная очередь и Smart History.
- **REQ-003** Строго сохранять порядок треков «Моей волны»; асинхронно готовить видео вперёд, но не переставлять треки.
- **REQ-004** Каждый **полный** запуск приложения создаёт новую сессию «Моей волны»; закрытие окон в трей сессию не сбрасывает. Запуск и пробуждение — без autoplay.
- **REQ-005** При недоступности Яндекса использовать загруженную очередь, затем Smart History; после восстановления API оставаться в Smart History до ручного переключения.
- **REQ-006** Постоянная история прослушивания в SQLite, включая повторы, дату/время, поиск, повторное воспроизведение, очистку. Действия: «сейчас», «следом», «в конец».
- **REQ-007** Smart History взвешивает лайки, частоту, давность; исключает дизлайки и быстро пропущенные композиции. Пропуски в My Wave не ухудшают историю.
- **REQ-008** Лайк/снятие лайка синхронизируются с Яндексом в обе стороны, по возможностям API; действия офлайн ставятся в очередь. Дизлайк немедленно переключает на следующий трек; история остаётся.
- **REQ-009** Отмена случайного дизлайка доступна 5 секунд, не возвращает предыдущий клип; удаление отрицательного фидбэка на стороне Яндекса — только если поддерживается.

## Видео и подбор
- **REQ-010 (уточнено пользователем)** Подбирать оригинального исполнителя/песню, исключая каверы, караоке, реакции, чужие ремиксы и минусовки. Из найденных подходящих кандидатов выбирать по просмотрам; официальность/тип видео — дополнительный сигнал. Имя загрузившего канала не обязано совпадать с исполнителем.
- **REQ-011** Разрешены отличающиеся live-аранжировки и длительности. Показывать **полное** YouTube-видео, включая вступления, аутро, аплодисменты; не обрезать по длительности аудиотрека.
- **REQ-012** Предпочитать 1080p+ при доступности, но релевантность важнее разрешения; качество YouTube IFrame нельзя гарантированно выставить/прочитать.
- **REQ-013** При отсутствии видео пробовать альтернативы, затем аудио Яндекса + визуализатор, **если доступ к аудио разрешён и реализуем**.
- **REQ-014** Пользователь вручную выбирает видео поиском или URL с ПК/телефона. Несколько избранных видео на один трек, случайный выбор на каждом воспроизведении (без непосредственного повтора при >=2), включая repeat-one; недоступное избранное → другое избранное → автоподбор → аудио.

## Воспроизведение и звук
- **REQ-015** Единая музыкальная сессия, одна общая громкость и **один звучащий источник** на все мониторы. Дублирующие плееры строго без звука.
- **REQ-016** На каждом мониторе собственный YouTube IFrame-плеер, если выбран одинаковый клип; синхронизация времени/состояния, без требования покадровой точности (**SPIKE**).
- **REQ-017** Пауза, play, next, previous, перемотка мышью и стрелками ±5 сек, время текущее/общее; tooltip при seek — **только время**, без превью кадров. Состояние синхронизировано на ПК и телефоне.
- **REQ-018** Previous: первое нажатие — в начало текущего видео; повторное в течение 3 секунд — предыдущий трек; при рестарте сохраняется paused-state. Одинаково для SMTC/телефона/ПК.
- **REQ-019** Repeat off, repeat-one для всех источников, repeat-queue только для конечных очередей (плейлист/альбом/ручная); My Wave бесконечная.
- **REQ-020** Переход видео↔видео/визуализатор: Fade to Black 300–500 мс, без аудиоперекрытия; визуализатор↔визуализатор: визуальный Crossfade 500–800 мс. Если визуализатор тот же, анимация непрерывна.
- **REQ-021** Без нормализации громкости; громкость приложения 0–100% независимо от master volume Windows, сохраняется, mute возвращает прежнее значение. Визуализатор должен реагировать на исходный аудиосигнал даже при громкости 0, **если технически возможно**.
- **REQ-022 (обновлено пользователем 2026-11-03)** Выходом звука управляет ОС. Приложение не выбирает/не закрепляет endpoint и не запрещает системный fallback; прежняя особая логика unplug/reconnect отменена.

## Мониторы, сцены, окна
- **REQ-023** Каждый монитор независимо показывает синхронизированный клип, выбранный визуализатор или выключенную сцену. Одна аудиосессия.
- **REQ-024** При отсутствии клипа сцена с видео временно показывает визуализатор, при следующем клипе возвращается к видео.
- **REQ-025** Визуализаторы: Ambient (обложка+свечение), Spectrum (полосы частот), Liquid (градиенты), Particles; на монитор фиксированный или случайный без немедленного повтора, собственные интенсивность/реактивность.
- **REQ-026** GPU WebGL; Canvas2D fallback только при недоступности/сбое WebGL, не из-за нагрузки. FPS и качество low/medium/high/ultra задаются **отдельно на каждый монитор**; не снижать автоматически при игре или GPU-нагрузке.
- **REQ-027** Доступные FPS: 30/60/90/120/144/165/180/240, ограниченные возможностями монитора; default — частота дисплея. Использовать обычный VSync/requestAnimationFrame, не обещать точный FPS в WebView2.
- **REQ-028** Реактивность визуализаторов — **реальный аудиосигнал только этого приложения**, WASAPI/process loopback + FFT/beat, без фиктивного BPM; общий поток анализа для всех мониторов (**SPIKE**).
- **REQ-029** Borderless fullscreen, не exclusive; F11 вход/выход, Esc выход; windowed/maximized/fullscreen, позиция, размер и монитор сохраняются. Always on Top отдельно на монитор, default OFF.
- **REQ-030** Закрытие окна скрывает **только это окно**; закрытие последнего оставляет приложение в трее. «Открыть» из трея восстанавливает все ранее скрытые окна, но не выключенные сцены. Полный выход — через трей.
- **REQ-031** Если монитор исчез из Windows, не переносить его сцену на другой дисплей; ждать подключения и восстановить на прежнем мониторе. Новый монитор настраивается вручную.
- **REQ-032** При выключении ТВ: если Windows видит отключение — приостановить/скрыть сцену; если не видит — ничего не менять. Аудио продолжает играть, если устройство вывода доступно.
- **REQ-033** Управление и курсор появляются лишь на мониторе с движением мыши, исчезают через 3 секунды бездействия на нём; hover/drag/menu предотвращают скрытие.
- **REQ-034** Постоянная панель названия и исполнителя (без обложки на видео), по умолчанию слева снизу, на выбор 4 угла; общие размер/прозрачность/позиция, отдельная видимость на каждом мониторе. Обложка используется на визуализаторах.

## Windows и управление
- **REQ-035** Стиль тёмный/стеклянный + кинематографичный, цвета могут подстраиваться к контенту. Анимированный splash с реальным статусом загрузки.
- **REQ-036** Никаких системных toast-уведомлений Windows; только уведомления внутри приложения. Windows SMTC и глобальные мультимедийные клавиши работают.
- **REQ-037** Обычные shortcuts работают **только при фокусе приложения**: Space play/pause, Left/Right ±5 сек, Up/Down громкость ±5%, F11 fullscreen, Esc выход; не срабатывают при вводе текста. Никаких дополнительных глобальных shortcuts.
- **REQ-038** Игра поверх окна на том же мониторе — обычный порядок окон Windows, приложение не перехватывает фокус; другие сцены продолжаются. Нет игрового режима, автоснижения FPS/качества или слежения за играми.
- **REQ-039** Аппаратное ускорение WebView2 включено постоянно, без пользовательского переключателя.
- **REQ-040** Пока играет музыка, блокировать **автоматический** сон Windows и **автоматическое** выключение дисплеев; при паузе/полном выходе снять блокировку. Ручной сон/выключение не блокировать.
- **REQ-041** После пробуждения восстановить соединения, текущую композицию/позицию и сцены, но оставить паузу до Play; не создавать новую My Wave-сессию.
- **REQ-042** Win+L: продолжать звук и защиту от сна; после разблокировки восстановить сцены; не обходить экран блокировки. Поведение WebView2 при lock — **SPIKE**.
- **REQ-043** Опциональный автозапуск Windows default OFF: запуск в трей, без autoplay.

## Пульт и надёжность
- **REQ-044** Пульт в браузере телефона в той же LAN; QR-подключение, одобрение первого подключения, доверенные устройства, отзыв доступа; несколько телефонов с равными правами.
- **REQ-045** Синхронизация через WebSocket; управление воспроизведением, очередью, лайками, историей, видео и мониторными сценами; единое состояние для всех клиентов.
- **REQ-046** При потере сети сохранять трек/позицию, не перескакивать автоматически, retry/backoff. При зависании YouTube после ~5 с buffering и ~15 с таймаута пытаться пересоздать плеер с seek; не допускать устаревших callback после смены трека.
- **REQ-047** Если кадр недоступен из-за cross-origin, не обещать его захват: оставить поверхность плеера и показать spinner/status.
- **REQ-048** Нет встроенного adblock, proxy, zapret, скачивания YouTube или обхода DRM; внешняя системная настройка сети пользователя не входит в приложение.

## Не входит в согласованный scope
Мобильное нативное приложение, видеоредактор, загрузка клипов, реклама/прокси, многоканальный раздельный звук, кастомизация shortcuts, встроенный эквалайзер/нормализация.

## Дополнения пользователя после исходного ТЗ

- **REQ-049** Целевые desktop-платформы: Windows, Linux, macOS. Это расширяет первоначальный Windows-only scope. Общая логика переносима, системные интеграции проверяются отдельно на каждой ОС.
- **REQ-050** Компактный миниплеер без лишних функций, пригодный для работы за компьютером с одним монитором. Показывает текущее видео/сцену общей музыкальной сессии; переход между полным интерфейсом и миниплеером не создаёт новую очередь, сессию или второй слышимый источник и не меняет pause/play.
- **REQ-051** Включаемый пользователем режим «поверх всех окон» для миниплеера — сценарий картинки в картинке во время работы. Работает и при одном мониторе. Не перехватывает фокус при обновлении трека. Действие системного topmost проверяется отдельно на Windows/macOS/Linux (включая ограничения оконного менеджера). Не обещать перекрытие системных защищённых экранов.

REQ-051 уточняет использование уже предусмотренного REQ-029 always-on-top для миниплеера. В обычном режиме поведение REQ-038 сохраняется; topmost включается явно, а не автоматически при работе в других приложениях.

## Изменение REQ-022 пользователем, 2026-11-03

Отдельный выбор аудиоустройства отменён: маршрутизацией управляет ОС. REQ-022 в части закреплённого endpoint, запрета системного fallback и обязательной ручной Play после возврата endpoint больше не применяется. Приложение не меняет системные настройки. На Windows/Linux/macOS используется системный выход. Общие no-autoplay на старте/после wake, один слышимый источник и громкость приложения сохраняются. S4 исключён из обязательных gates, S6 app-only capture остаётся открытым.

## Гостевой доступ — уточнение пользователя 2026-11-05

- **REQ-052** Общедоступные возможности Яндекс Музыки доступны в Encore без входа: поиск каталога, исполнители и их треки, альбомы, публичные плейлисты, актуальный чарт. Полученные списки можно воспроизводить через существующий подбор YouTube. Персональная «Моя волна», личные/закрытые коллекции и синхронизация реакций требуют авторизации; приватность ресурса определяется ответом Яндекса. Не подменять персональный источник локальной историей при отказе авторизации. Доступность других неперсональных блоков расширять по проверенным возможностям сервиса, не выдавать их отказ за отсутствие всех публичных данных.

## Независимое содержимое окон — уточнение пользователя 2026-11-05

- **REQ-053** Пользователь независимо выбирает для каждого окна клип, визуализатор либо только панель управления без клипа и без визуализатора. Обязательный сценарий: на телевизоре показывается клип, на основном мониторе остаются только управление/поиск/списки. Выбор не связан с тем, какое окно является основным, и не меняет общую очередь, позицию, громкость или pause/play. Один источник звука сохраняется. Настройки окон и их мониторов запоминаются. Прежнее правило постоянно видимого видео относится к обычной компоновке «Сцена» и не запрещает явно выбранный режим только управления.
