# Мониторы, сцены и визуализаторы

## Актуальная реализация REQ-056/057 — 2026-11-05

Windows: один настоящий YouTube engine + DWM mirrors. Кнопка «Экраны» из основного окна → явный выбор монитора → клип. На каждом мониторе можно открыть независимое зеркало, выключение относится к выбранному экрану. Основное окно может оставаться CONTROLS. Реальные два дополнительных окна и меняющиеся пиксели второго, один source и отсутствие iframe в UI прошли native-проверку. Визуализаторы ещё недоступны до S6; hotplug/persistence следующие. Linux/macOS — встроенный основной плеер, дополнительных зеркал пока нет. См. docs16; остальное ниже содержит историю и будущую целевую модель, а не перечень полностью готовых возможностей.

**REQ056, уточнение пользователя 2026-11-05:** описание собственных iframe каждой сцены ниже историческое и отменено. Целевая схема — один настоящий плеер и локальные зеркала. Spike DWM на Windows подтвердил, что alpha0/clickthrough source сохраняет живые кадры, настоящий hide замораживает. Продуктовая интеграция отдельного прозрачного источника ещё не готова; не путать число UI WebViews с числом YouTube-плееров (ADR033).

## Текущий срез — 2026-11-05

Добавлен явный выбор экрана в настройках окна клипа и обновление списка дисплеев. Windows возвращает per-monitor interface ID, geometry/DPI/primary и nominalHz; временный ID на неподтверждённых платформах явно отличается по stable=false. Native проверка прошла для3 реальных подключённых дисплеев, включая последовательный перенос одного окна на каждый. Неверный/отключённый ID отклоняется без подмены. Persistence и hotplug пока следующие задачи (ADR032).

Настройки → «Окно клипа» открывает одно отдельное VIDEO-окно, которое можно вручную перенести на ТВ. Основное окно независимо переключается в «Только управление». Общая очередь/transport/звук остаются в основном окне, follower всегда muted и не продвигает очередь. Крестик скрывает сцену, tray Open показывает, «Выключить окно» полностью уничтожает. Скрытый follower не держит iframe. Подтверждены Windows native реальные два YouTube, muted/volume0, общая pause, main hidden6с, fullscreen/topmost/off и IPC guards; см. ADR031. Выбор дисплея/persistence/несколько сцен/hotplug/visualizers ещё не реализованы; полную матрицу ниже этот срез не закрывает.

## Мониторная модель
`monitor_id` (стабильная Windows идентичность), `name`, `bounds`, `refresh_hz`, `connected`, `scene_mode`, `window_mode`, `position`, `size`, `always_on_top`, `info_visible`, `fps_cap`, `quality`, `visualizer_preset`, `preset_policy`, `intensity`, `reactivity`.

## Сцены
- `VIDEO`: собственный YouTube IFrame, синхронизированный с общим треком; muted кроме единственного audio authority.
- `VISUALIZER`: свой рендер, общий аудиоанализ; preset fixed/random (без немедленного повтора).
- `OFF`: сцена не создаёт окно и не рендерится.
- Если видео отсутствует, `VIDEO` временно отображает визуализатор, затем возвращается к видео.
- Отключённый дисплей: не переносить его окно на другой; восстановить на том же дисплее после подключения. Новый дисплей — ручная настройка.

## Визуализаторы
1. **Ambient:** обложка альбома, пульсирующий свет и мягкое свечение.
2. **Spectrum:** полосы FFT с адаптацией к громкости/частотам.
3. **Liquid:** плавные градиентные формы и движение от ритма.
4. **Particles:** частицы с реакцией на бас/транзиенты.
- Визуализаторы должны работать без подмены реального анализа вымышленным BPM.
- Обложка допускается только в визуализаторе; поверх клипа в info panel — только title + artist.

## Производительность
- WebGL hardware acceleration ON, без переключателя.
- Canvas2D fallback при реальной недоступности/ошибке WebGL; не переключать автоматически из-за игры/нагрузки.
- FPS options: 30,60,90,120,144,165,180,240; отфильтровать по заявленной частоте монитора; default = refresh_hz (если точного пункта нет, ближайший допустимый не выше refresh_hz — предложение).
- rAF/VSync; лимит FPS — максимум, не гарантия. `quality`: low/medium/high/ultra, независимый от FPS.
- Скрытые окна не должны активно рендерить. При этом звук не должен зависеть от видимости конкретного окна.
- Никакого auto game detection, auto GPU throttling, auto FPS lowering.

## Окна
- Borderless fullscreen на дисплее, Alt+Tab; F11 переключает, Esc выходит.
- Windowed/maximized/fullscreen, размер/позиция/монитор сохраняются; always-on-top отдельно, default OFF.
- Закрытие конкретного окна → hide; tray Open → восстановить все ранее скрытые, кроме `OFF`.
- Если Windows считает выключенный телевизор подключённым — не менять состояние.

## Инфопанель и управление
- Title + artist постоянно видимы, default нижний левый угол, выбор из 4 углов, общие настройки размера/opacity/position, per-monitor visibility.
- Курсор/контролы видимы только на мониторе с мышью; через 3 с неактивности скрываются; hover/drag/menu удерживает.
- UI overlay не должен блокировать YouTube player controls и seek там, где используется собственная шкала.

## Тестовая матрица
- 1 монитор, 2 монитора, 3 монитора; разные DPI, 60/120/144/180 Hz.
- Монитор HDMI отключился и вернулся, идентичность сохранена.
- TV power-off, Windows считает дисплей подключённым.
- Полноэкранная игра поверх одного окна, остальные работают.
- Один/несколько видео-плееров + визуализаторы; нет двойного звука.
- WebGL context lost → Canvas2D; возвращение по решению реализации, без бесконечного фликера.

## Миниплеер на одном дисплее

REQ-050/051: миниплеер не требует второго монитора и не создаёт дополнительную музыкальную сессию. Режим поверх окон включается вручную. Компактный размер окна не должен автоматически менять настройки FPS/качества сцены. Оконные адаптеры и ограничения topmost проверяются на Windows, macOS и Linux отдельно.

## Уточнение REQ-053: контроллер — самостоятельный режим окна

К VIDEO/VISUALIZER/OFF добавляется CONTROLS: видимое окно с транспортом, поиском, очередью, медиатекой и настройками, без показываемого видеоклипа/визуализатора и без пустого места под них. OFF по-прежнему означает отсутствие окна, а не панель управления. Содержимое каждого окна выбирается отдельно: ТВVIDEO + основнойCONTROLS; ТВVISUALIZER + основнойVIDEO; несколькоVISUALIZER с разными пресетами. Эти примеры не являются жёсткими шаблонами.

Смена режима одного окна не меняет другие сцены и не создаёт новую музыкальную сессию. Все окна управляют одним coordinator. Позиция, размер, монитор и режим сохраняются независимо. Сохранение единственного audio authority при смене VIDEO→CONTROLS и исчезновении ТВ требует S5/platform проверки; не объявлять уже реализованным и не плодить второй слышимый player. Требование «видео всегда видно» обычного Scene UI не применяется к явно выбранномуCONTROLS.

Приёмка: запустить клип на ТВ, переключить основной экран вCONTROLS, продолжить музыку; на основном нет ни видео, ни визуализатора, поиск/транспорт доступны. Смена ТВ наVISUALIZER не меняет режим основного. После перезапуска режимы/мониторы восстановлены, autoplay отсутствует. Отключение/возврат ТВ следует REQ031/032, а управляющее окно остаётся доступным.

REQ-053 дополнен пользователем: в CONTROLS вся площадь окна занята списками и управлением, без пустого видеослота. Предусмотреть одновременно видимые каталог/плейлист и очередь, постоянный transport и доступ к альтернативам/настройкам остальных сцен. Компоновка адаптируется независимо от содержимого ТВ; точное размещение панелей описано как рабочее предложение в docs07.
