# Источники, очередь, история и реакции

## Каталог источников
- `MY_WAVE`: бесконечная рекомендательная последовательность, серверный порядок неизменен; новая сессия на **полный запуск**.
- `LIKES`, `PLAYLIST`, `ALBUM`, `ARTIST`, `SEARCH`: выбор контента через Яндекс; некоторые источники конечные, artist/search могут быть контекстными — зафиксировать semantics в адаптере.
- `MANUAL`: вставленные пользователем композиции, сохраняют порядок вставки и приоритет относительно потока.
- `SMART_HISTORY`: автономная выборка из локальной истории, ручной или автоматический вход при отказе API.

## Очередь: модель
`QueueItem(id, track_key, source, source_session_id, source_ordinal, inserted_at, insertion_kind, resolution_state, metadata_snapshot)`.
- Для My Wave `source_ordinal` монотонен, выдача **не сортируется** по скорости поиска видео.
- Пользовательские `PLAY_NOW`, `PLAY_NEXT`, `APPEND` вставляются в отдельную логическую очередь, не переписывая рекомендации.
- `PLAY_NOW`: текущий трек уходит в историю и выбранный запускается сейчас; дальнейшее поведение исходного потока сохраняется.
- `PLAY_NEXT`: FIFO по порядку ручных вставок (рекомендуемая семантика; см. открытые вопросы).
- `APPEND`: в конец конечной очереди или ручного буфера при бесконечной My Wave.
- Фоновый prefetch metadata/video для следующих K элементов (стартовый K=3–5 — **предложение**); невозможность найти клип не блокирует порядок.

## Repeat
- `OFF`: обычное продвижение; у конечного источника остановка в конце, у My Wave — следующая рекомендация.
- `ONE`: повтор текущего трека; при каждом цикле заново случайно выбирать видео из избранных, избегая предыдущего при >=2.
- `QUEUE`: повтор конечной очереди; недоступен для My Wave. Не включать для Smart History как конечной очереди.

## Previous / next
- Previous первый раз: seek(0) текущего видео и сохранение pause/play; второй раз в интервале 3 с — предыдущая композиция из playback stack.
- После 3 с окно двойного Previous сбрасывается. Переключение трека, смена источника и явный seek сбрасывают счётчик (предлагаемое уточнение).
- Next всегда означает следующий **трек**, не следующее видео той же композиции.

## История
- Писать отдельную запись `play_event` на каждый фактический старт, включая repeat-one; хранить время, source, video_id, длительность, процент/секунды прослушивания, способ завершения (natural, skip, dislike, error, shutdown).
- История переживает рестарты; фильтры по дате, текстовый поиск, действия «играть сейчас», «следом», «в конец», очистка с подтверждением.
- Не удалять историю при дизлайке; дизлайк исключает трек из Smart History.

## Smart History
- Кандидаты — уникальные track_key из истории, исключая dislike и **подтверждённые** quick-skip.
- Взвешивание: лайки + частота + давность, случайная выборка по весам, анти-повтор. Формула/коэффициенты — техническое предложение, подбираются тестами.
- **Важное уточнение:** обсуждался порог «3 пропуска в первые 15 секунд», но он не был отдельно утверждён; считать это **предлагаемым default**, не продуктовым законом.
- Пропуски во время My Wave **не учитываются** для quick-skip исключений.
- Если API Яндекса недоступен: доиграть доступные загруженные элементы, перейти в Smart History; после восстановления **не** переключаться обратно без выбора пользователя.
- Если Smart History пустая: сообщить об отсутствии локальных треков, не генерировать фиктивные рекомендации.

## Лайки/дизлайки
- Local optimistic UI + persistent outbox для синхронизации с Яндексом; idempotency/dedup.
- Лайк: поставить/снять и отразить внешние изменения при sync (политика конфликтов — в `13`).
- Дизлайк: немедленный next; показать Undo 5 с; local exclude сразу. Если API не поддерживает обратный negative feedback, честно показывать, что локальная отмена выполнена, а внешнюю нельзя гарантировать.
- Не обещать возможность «снять дизлайк» на Яндексе без проверки конкретного API.

## Ошибки источника
- Auth expired: не терять локальные данные, запросить повторную авторизацию внутри приложения.
- Rate limit: backoff с jitter, без агрессивного polling.
- Network offline: сохранить очередь и позицию, не перепрыгивать композицию из-за ошибки сети.
- Различать «источник недоступен» и «нет клипа».

## Поиск каталога Яндекс Музыки

В интерфейсе есть отдельный поиск исполнителей, треков, альбомов и плейлистов. Используется search(type=all, nocorrect=False); исправления и транслитерация приходят от Яндекса. Нет локальной имитации каталога. Поиск и чтение коллекций выполняются native-клиентом с токеном из OS store; секрет не передаётся в UI.

Просмотр карточек/списков не меняет текущую очередь. Отдельные действия запускают трек или список с выбранного места. Серверный порядок/повторы сохраняются. Конечная очередь коллекции подгружает следующие страницы, если они есть; по завершении не переключается самовольно в My Wave. Полный запуск приложения по-прежнему создаёт новую Wave-сессию без autoplay.

Артист: artists/{id}/tracks по 50, порядок сервиса. Альбом: тома/диски сохраняются, UI-страницы по 100. Плейлист: users/{uid}/playlists/{kind}, UI-страницы по 100. Большие ответы по-прежнему ограничены 2 МБ native транспортом; необычные/private/огромные коллекции требуют дополнительных проверок. Недоступная запись с валидным ID остаётся на своём месте с пометкой, а не переставляет следующую.

## Уточнение пользователя 2026-11-04: непрерывный поток клипов

Это утверждённое требование к следующему срезу, а не описание уже реализованного поведения.

- После явного включения «Моей волны» Encore самостоятельно выдаёт непрерывную последовательность видеоклипов. Ручной выбор/замена доступны по желанию, но не являются обязательным шагом.
- Заранее получать следующие рекомендации и параллельно подбирать кандидатов для нескольких треков. Размер буфера/число запросов — технические параметры; поддерживать запас, пополнять до исчерпания.
- Порядок рекомендаций сохраняется среди пригодных треков. Нет подходящего уверенного совпадения, требуется подтверждение или клип недоступен — автоматически пропустить рекомендацию. Поздний ответ по пропущенному треку не прерывает текущий.
- На текущем треке пробовать альтернативы в ограниченный срок; ошибка embed, таймаут подготовки или зависание воспроизведения не должны оставлять волну на ручном выборе. После исчерпания бюджета переходить дальше.
- Для My Wave нужен именно поток видео: прежний audio/visualizer fallback не заменяет отсутствующий клип в этом режиме. Это уточняет REQ-013/014 только для сценария волны.
- Нет сети/сервис недоступен — ограниченные автоматические повторы с backoff и понятный статус. Не путать общую сетевую ошибку с плохими композициями и не прокручивать рекомендации бесконечным быстрым циклом запросов. Технические пропуски не являются dislike/плохим музыкальным вкусом пользователя.
- Явная Pause/Stop и sleep/wake отменяют автоматическое продолжение до Play; полный запуск по-прежнему без autoplay. «Включить волну» является явным действием запуска.
- В fullscreen не загрузившийся клип автоматически сменяется следующим в том же источнике, без выхода из fullscreen и обязательного диалога. Для конечных списков сохраняются правила конца/repeat, источник не подменяется волной.
- UI: видео и управление постоянно видны. Прокрутка поиска, выдачи, истории и очереди не уносит их за пределы экрана.
