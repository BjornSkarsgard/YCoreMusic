# Instructions for Codex — Музыкальный телевизор

Ты работаешь над desktop-приложением Encore для Windows, Linux и macOS.

## Перед началом
1. Прочитай `docs/00-README.md`, `docs/01-PRODUCT-DECISIONS.md`, `docs/02-ARCHITECTURE.md`, `docs/10-RISKS-AND-SPIKES.md`, `docs/11-ROADMAP-AND-ACCEPTANCE.md`.
2. Прочитай профильные `docs/03`–`09`, если задача относится к подсистеме.
3. Проверь `docs/13-OPEN-QUESTIONS.md`: не выдавай предложенные дефолты за согласованные.
4. Если репозиторий пуст — сначала предложи план **Этапа 0**, без реализации всех функций сразу.

## Инварианты
- Один источник звука, один authoritative playback coordinator, одна очередь.
- REQ-056: один настоящий YouTube-плеер/загрузка видео. Дополнительный показ — только локальное зеркало после spike, без второго iframe/декодирования/сетевой загрузки. Прежний REQ016 с несколькими iframe отменён уточнением пользователя 2026-11-05.
- My Wave: порядок не менять. Full launch: новая сессия, без autoplay.
- Аудиовыходом управляет ОС; отдельный выбор/закрепление endpoint отменён пользователем. Не менять системный default из приложения.
- Не использовать скрытый YouTube audio extraction, DRM bypass, встроенный adblock/proxy.
- Важные внешние интеграции сначала проверяются spike.
- Никаких глобальных обычных hotkeys; только SMTC media keys.
- Отдельные настройки сцены/FPS/качества каждого монитора; не включать авто игровой режим.

## Рабочий процесс
- Перед задачей кратко опиши план и затронутые требования (`REQ-...`).
- После задачи: файлы, тесты, результат, риски, что осталось.
- Не записывай токены в код, конфиги, логи и коммиты.
- Для архитектурных компромиссов веди ADR, для статуса — `docs/IMPLEMENTATION-STATUS.md`.
- Не объявляй функцию готовой, если требуемый Windows/YouTube/Yandex сценарий не проверен.
